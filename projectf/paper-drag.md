## 한 줄 정의

> 속도를 **뚫는 쪽**과 **비탈 쪽** 두 조각으로 쪼개고, 각자 다른 브레이크로 깎은 뒤, 다시 더한다.

## 1. drag = 공기저항 = 속력을 빼는 브레이크

| | 하는 일 | 우리 코드 |
|---|---|---|
| 중력 | 매 순간 속력을 더함 | `PaperSim`의 Gravity |
| drag | 매 순간 속력을 뺌 | `PaperAero`의 NormalDrag, PlaneDrag |

- 둘이 비기면 속력이 일정해짐 (더 안 빨라짐)
- 빼는 쪽이 없으면 속력이 계속 쌓임 (점점 빨라짐)

## 2. 같은 종이라도 움직이는 방향에 따라 저항이 다르다

- 달리는 차 창밖으로 손을 내밀면: 손바닥을 펼치면 확 밀리고, 칼날처럼 세우면 거의 안 밀림
- 종이는 **휘지 않는 판**으로 계산함. 두 값은 종이의 부분(가운데/가장자리)이 아니라 **움직이는 방향**을 나눔

| 브레이크 | 맡은 방향 | 다른 방향에는 |
|---|---|---|
| NormalDrag | 면을 **뚫는** 쪽 (N 방향). 손바닥 | 손도 안 댐 |
| PlaneDrag | 면을 **따라가는** 쪽 (비탈). 칼날 | 손도 안 댐 |

- 둘은 "하나가 모자라서 다른 하나가 채워 주는" 관계가 아님. **맡은 방향이 아예 다름**
- Normal은 "보통"이 아니라 **법선(N)**

## 3. 한 프레임에 일어나는 일

1. **지금 속도** — 기울어진 종이가 아래로 떨어지는 중
2. **쪼개기** — 속도를 뚫는 쪽 조각 + 비탈 쪽 조각으로. 두 조각을 꼬리에 이어 붙이면 원래 속도 = **벡터의 덧셈**
3. **따로 깎기** — 뚫는 쪽은 많이, 비탈 쪽은 조금
4. **다시 더하기** — 똑바로 아래였던 속도가 비탈 쪽으로 꺾임 = **미끄러짐**

## 4. 깎는다 = 화살표 길이에 비율을 곱한다

| 조각 | 남기는 비율 (예시) | 길이 100이었다면 |
|---|---|---|
| 뚫는 쪽 | 30% | 100 → 30 |
| 비탈 쪽 | 90% | 100 → 90 |

- **같은 비율**로 깎으면 방향은 그대로, 길이만 줄어듦 → Unity `Rigidbody.drag`가 이것. 그래서 Unity drag만으로는 종이가 천천히 똑바로 떨어질 뿐 미끄러지지 않음
- **다른 비율**로 깎으면 다시 더했을 때 방향이 꺾임 → 종이 drag
- 30%·90%는 보이게 과장한 숫자. 실제로는 한 프레임에 조금씩(NormalDrag 8, 60fps면 약 13%), 1초에 60번

## 5. 회전 없이 미끄러질 때: PlaneDrag가 하는 일

- 회전이 없으면 미끄러지는 **방향은 계속 같음**
- PlaneDrag 0 → 비탈 쪽에 브레이크가 없어서 **계속 빨라짐** (빙판 비탈의 썰매)
- PlaneDrag 있음 → 처음엔 빨라지다가 **어느 속력에서 일정해짐** (눈밭)
- NormalDrag만 있으면 왜 점점 빨라지나: NormalDrag는 비탈 쪽을 **0만큼** 막음. 중력이 비탈 쪽으로 더해 주는 속력이 빠지지 않고 계속 쌓임

## 6. 코드와 그림 연결

```hlsl
float3 vn = dot(Vel, N) * N;                              // 쪼개기: 뚫는 쪽 조각
float3 vt = Vel - vn;                                     // 쪼개기: 나머지 = 비탈 쪽 조각
float keepN = max(0.0f, 1.0f - NormalDrag * DeltaTime);   // 뚫는 쪽 남길 비율
float keepT = max(0.0f, 1.0f - PlaneDrag  * DeltaTime);   // 비탈 쪽 남길 비율
OutVel = vn * keepN + vt * keepT;                         // 따로 깎고 다시 더하기
```

| 줄 | 그림에서 | 메모 |
|---|---|---|
| `vn = dot(Vel, N) * N` | 뚫는 쪽 조각 | `dot`이 "N 쪽으로 몇 cm/s인가"를 구함. **여기가 내적** (2층에서 따로) |
| `vt = Vel - vn` | 비탈 쪽 조각 | 전체에서 뚫는 쪽을 빼면 남는 것 |
| `keepN`, `keepT` | 남기는 비율 | `max(0, …)`는 비율이 음수(속도 반전)가 되는 것만 막음 |
| `OutVel = …` | 새 속도 | 꼬리에 이어 붙이는 벡터 덧셈 |

- 이번엔 `Vel`을 normalize하지 않음. 방향 비교가 아니라 "몇 cm/s"가 필요해서. 속도 0일 때 0으로 나누기도 없음

## 7. 조절 값 정리

| 값 | 지금 | 키우면 | 없으면 (0) |
|---|---|---|---|
| NormalDrag | 8 | 더 둥둥, 옆으로 더 많이 미끄러짐 | 돌멩이처럼 뚝 떨어짐 |
| PlaneDrag | 0.5 | 덜 미끄러짐 | 미끄러지는 속력에 한계 없음 |

- 왔다 갔다(흔들림)는 이 두 값이 아니라 `FlipStrength` 담당 → 회전 편

## 8. 직접 해 본 실험

| 설정 | 본 것 | 알게 된 것 |
|---|---|---|
| NormalDrag 50 | 기울어진 각도대로 퍼지며 둥둥 | 뚫는 쪽이 막히면 면을 따라 미끄러질 수밖에 없음 |
| PlaneDrag 0, FlipStrength 30 | 쭉 나아가지 않음 | 흔들리면 미끄러지는 방향이 계속 바뀌어서 |
| PlaneDrag 0, FlipStrength 0 | 한 방향으로 점점 빠르게 | 비탈 쪽에 브레이크가 없으면 속력이 계속 쌓임 |

## 9. 헷갈렸던 것

- **종이가 U자로 휘어서 가운데와 가장자리 저항이 다른 건가?** → 아니요. 휘지 않는 판. 방향을 나눔
- **PlaneDrag가 크면 더 많이 회전하나?** → 아니요. PlaneDrag는 미끄러지는 속력만 깎음
- **PlaneDrag 없이 NormalDrag만 있어도 되지 않나?** → 지금 장면(3m 낙하 + 흔들림)에선 거의 차이 없음. 4단계에서 몸이 종이를 모서리 방향으로 세게 날릴 때를 대비해 0.5 유지 (취향 · 바꿔도 됨)
- **"스르륵"이면 점점 느려진다는 건가?** → 아니요. 회전 없으면 같은 방향으로, 처음엔 빨라지다가 일정한 속력이 됨
