## 티키타카 — 질문하고 배운 것

### Q. 내적은 서순이 상관없나? `dot(Vel, N)`이랑 `dot(N, Vel)`이 같아?

- 같다. 칸끼리 곱해서 더하는 것뿐이라 곱셈 교환법칙(초등)
- 외적은 순서를 바꾸면 축이 정반대 (미사일 실험에서 "딱 반대로" 간 것)
- ② 공기저항에서 순서가 중요한 건 dot 안이 아니라 dot 결과에 **무엇을 곱하느냐** (`* N`)

### Q. 외적·내적으로 torque가 어떻게 도는지 (지도 ③)

- 질문 흐름: `cross(N, V)`면 N → V로 도는 방향? → "축을 뒤집는다"는 게 무슨 뜻? → 내적도 "어디로"를 말하는 것 같아 헷갈림 → 외적이 축이라는 게 안 와닿음
- 깨달은 문장: **"N과 V로 이루어진 평면에 수직선을 꽂는데, 그걸 앞으로 꽂을지 뒤로 꽂을지는 내적으로 정하는 건가!?"** → 맞음
- 자세한 건 노트로: [꼬챙이로 보는 torque](../../game-math/torque-skewer.md), [내적은 숫자, 외적은 화살표](../../game-math/dot-cross.md)

### Q. 충돌은 어떻게 하기로 했지? 캐릭터 메시랑? 신체에 작은 충돌체?

- 10-11 결정: **부위별 작은 구(발 L/R·골반·가슴·머리) × 그 부위의 속도**
- 영상 근거: 서 있으면 반응 없음 → 속도 필요 / 휘두르는 발이 지나간 종이만 섬 → 부위별 / 바닥 종이는 뒤집힘 → 회전이 주 반응
- 실제 충돌체가 아니라 **종이가 스스로 재는 거리**. 수백 장 CPU 파티클이라 메시 충돌로는 부위별 속도를 얻기 어려움

### Q. 신체 부위별 속도를 구할 수가 있어?

- 위치는 엔진이 줌: `GetMesh()->GetSocketLocation(TEXT("foot_l"))` (뼈 이름도 됨)
- 속도는 직접 계산 — 작업자가 먼저 말함: **`(지금 위치 − 이전 위치) / DeltaTime`** → 맞음
- `÷ DeltaTime`이 왜 속력인지에서 오래 막힘 → 원인은 소수 나눗셈. 깨달은 문장: "속력은 거리 / 시간이고, 한 프레임에 이동한 양 / 한 프레임의 시간이니까 당연히 나눠야 하는 게 맞지"
- 자세한 건 노트로: [거리 · 속력 · 시간](../../game-math/distance-speed-time.md)

### Q. Niagara로는 어떻게 넘기지? (솔직히 기억 안 남)

- **USER** 태그. 2단계에서 `USER FloorZ (float)`로 바닥 높이를 넣었던 그 방법 (지금은 트레이스로 바뀌어 안 씀)
- PARTICLES = 종이마다 / INPUT = 스택에서 손으로 / **USER = 바깥(BP·C++)이 실행 중에 넣음** / ENGINE = 엔진이 줌

### Q. 발이 나한테 닿았나? → 거리로 측정하지 않을까

- 맞음 (작업자 제안). 미사일 `FVector::Dist(...) <= HitDistance`와 같은 모양
- HLSL: `length(FootPos - Pos)` + `step(dist, FootRadius)` → 구 안이면 1 (if 대신 0/1)

### Q. 닿았다면 닿은 순간 종이에게 velocity를 줘야 하지 않을까?

- 좋은 방향 (작업자 제안). 지금 코드에 대 본 예측
  - 옆으로만 주면 PaperSim의 `OutVel *= airborne`가 바로 0으로 만듦 → **위쪽 성분 필요**
  - 위로 떠오르면 `Landed` = 0 → 3단계 torque가 다시 켜져서 **저절로 뒤집힐 수도** 있음
  - 바닥(`Landed` = 1)에서는 settle이 각속도를 덮어써서, 회전만 직접 주면 지워짐
- "닿은 위치를 기준으로"는 더 깊은 아이디어: 가운데를 밀면 밀려나고 모서리를 밀면 돈다 = `cross(가운데→닿은 곳, 미는 힘)`. 아직 안 와닿음 → 4-1b로 미룸
