```
[BeginPlay]
Get Player Character (0)
  → Get Components by Class (Component Class: Paper Toucher Component)
  → SET Touchers            (Paper Toucher Component, Object Reference, 배열)

[Tick]
Touchers → Get (a copy) [0] → Is Valid?
  ├ Part Pos → Set Niagara Variable By String (Position)  In Variable Name: FootPos0

  ├ Part Pos → Set Niagara Variable By String (Position)  In Variable Name: FootPos1
  └ Part Vel → Set Niagara Variable By String (Vector3)   In Variable Name: FootVel1
```

## 티키타카 — 질문하고 배운 것

### Q. 이제 양발 끝에 구를 달면 되나?

- 구는 **디버그 그림**일 뿐, 종이를 미는 게 아니다. 종이는 Niagara가 받은 `USER FootPos`/`FootVel` 한 쌍만 안다
- 데이터는 세 칸을 지나간다: **캐릭터(컴포넌트) → BP_PaperField(Set) → NS(모듈)**. 발을 늘리려면 세 칸 모두 바뀌어야 한다
- 목표를 둘로 자름: 4-1b-1(1명 양발) → 4-1b-2(3명)

### Q. 언리얼에서 같은 컴포넌트를 여러 개 붙일 수 있나? 유니티는?

- 둘 다 된다. 첫 번째 하나만: `Get Component by Class` = `GetComponent<T>()`, 전부: `Get Components by Class` = `GetComponents<T>()`
- 4-1a의 BP는 단수형이라, 컴포넌트를 2개 붙여도 하나만 가져왔을 것

### Q. 반복문을 돌려야 하나? Niagara는 Array로 받아서 돌려야 하나?

- 반복문을 돌려도 받는 쪽 이름이 `FootPos` 하나면 **마지막 발만 남는다** (덮어쓰기). 받는 쪽부터 정해야 한다
- A. 모듈 2번 쌓기 vs B. 배열 하나 + HLSL `for` → A를 택함. B는 CPU VM에서 `for`가 되는지 확실치 않고 새로 배울 게 많다

### Q. 왼발용·오른발용 2개를 넣어서 동시에 돌리는 거네?

- 동시가 아니라 **위에서 아래로 차례대로**. 두 번째 모듈은 첫 모듈이 바꾼 속도를 이어받아 다시 섞는다 → 둘 다 반영된다

### Q. Rename을 해도 `(Scratch Module 03)`은 안 바뀌네?

- 굵은 글씨 = 스택에 놓인 **이 모듈 하나의 표시 이름**, 회색 = **스크립트 자체의 이름**
- + 메뉴는 스크립트 이름으로 찾는다 → 그래서 `PaperInfluence`로 검색해도 안 나왔다
- 우클릭 메뉴에 Rename이 없을 땐 **선택 → 잠깐 쉬고 → 한 번 더 클릭** (콘텐츠 브라우저·아웃라이너·탐색기와 같은 동작)

### Q. BP_PaperField에 `ToucherFoot_l`, `ToucherFoot_r` 변수를 따로 만들어야 하나?

- 배열 순서가 보장되지 않아서 `Foot_L`이라는 이름이 **거짓말**이 될 수 있다. Niagara는 왼발·오른발을 똑같이 처리하므로 구분할 필요도 없다 → 배열 하나 `Touchers`

### Q. Array가 왜 이렇게 많노? / Array에 크기를 세팅해줘야 하는구나

- Variable Type 줄에는 버튼이 둘이다: **타입**(Paper Toucher Component) + **담는 모양**(Single / Array / Set / Map). 이름에 Array가 들어간 구조체 목록은 앞의 버튼이었다
- 크기는 정하지 않는다. BP 배열은 C# `List`처럼 늘어나고(`TArray`), BeginPlay의 `SET`이 배열을 통째로 바꾼다

### Q. 왜 1번 인덱스에서는 PartPos가 안 받아와지지? None인 것 같은데

- 두 GET의 출력 핀 툴팁을 나란히 놓고 보니, 다른 건 `None`이 아니라 **타입 줄**이었다

| | GET [0] | GET [1] |
|---|---|---|
| 타입 | Paper Toucher Component Object Reference | **Object Reference** |
| Current value | None | None (게임이 안 돌 때는 원래 None) |

### Q. 이게 버그임? → 재현 실험

- Claude 설명: "와일드카드 GET은 처음 들어온 배열로 타입을 정하고 다시 안 정한다"
- 작업자: "그러면 빈 GET을 배열에 연결해도 재현돼야 하는데 안 된다" → **Claude 설명이 틀렸음**
- 새 가설: `Is Valid`의 `Input Object`(Object 핀)에서 **거꾸로** 끌어내 GET을 만들면 출력이 Object로 정해지고, 나중에 배열을 꽂아도 자식 타입이라 다시 정하지 않는다 → 작업자가 **재현 성공**, 원인 확정
- 깨달은 것: 와일드카드 노드는 **값을 주는 쪽(입력)부터** 연결. 타입이 정해진 노드는 거꾸로 끌어내도 괜찮다 → [함정 모음](../../unreal/pitfalls.md)

### Q. 종이가 캐릭터를 통과 못 하는데(영상), 이건 로드맵에 있나? 펄럭거림은?

- 몸 반응 설계가 "부위 속도로 차기"까지만 있고 **구 밖으로 밀어내기**가 빠져 있었다. 서 있는 몸은 그대로 관통한다
- 3단계 "펄럭"은 판 전체가 기울고 도는 것. 판 자체가 휘는 것은 로드맵에 없다 → 머티리얼 WPO + Dynamic Material Parameter (SM_Paper 4×6 분할 활용)
- 작업자 결정: 로드맵에 넣지 말고 "디테일을 챙기면 이런 것까지" 후보로만

## 🚨 오늘 걸린 함정 (습관 경보)

- **Set 노드 `In Value`가 빈칸** — 변수 타입을 바꾸며 예전 Get 노드가 지워질 때 `PartPos`/`PartVel` 선도 같이 사라짐. 핀에 `X 0.0 Y 0.0 Z 0.0` 입력칸이 보이면 **안 꽂힌 것**. 그대로면 FootVel이 0 → `w = 0` → 양발 모두 반응 없음
- **`GET [1]`이 Object로 굳음** — 메뉴 제목 `Actions taking a(n) Object Reference`. 지우고 `GET [0]`을 복사해서 해결
- **`Can't parse default value 'None' for Touchers. Property: Touchers.`** (Compile 경고) — 단일 오브젝트일 때의 기본값 문자열이 남음. Default Value에서 원소 ⊕ 추가 → 🗑 삭제로 해결
- 🚨 습관 경보 (예방): `GET [1]` 뒤에 `Cast To PaperToucherComponent`를 붙여 덮지 말 것 — 타입이 틀린 원인은 남고 매 Tick Cast 비용과 실패 분기만 생김 (커뮤니티 표준: 노드를 새로 만들어 타입을 바로잡음)
- 이름 오타는 조용히 실패 — `Set Niagara Variable By String`은 이름을 문자열로 찾아서 틀려도 에러가 없다
