## 최종 코드

### M_Paper1 (World Position Offset) — 노드를 HLSL로 읽으면

```hlsl
float  u     = TexCoord.x;            // TexCoord → Mask(R)
float  c     = (u - 0.5f) * 2.0f;     // ConstantBiasScale (Bias -0.5, Scale 2)
float  shape = c * c;                 // Multiply ①
float  lift  = shape * Bend * 3.0f;   // Multiply ② (Dynamic Parameter Param1) ③ (BendDepth 3)
float3 wpo   = lift * VertexNormalWS; // Multiply ④ → World Position Offset
```

### Dynamic Material Parameters · Index 0 · Param1 (New Expression)

```hlsl
Particles.PaperBend * (1.0 - Particles.Landed)
```

### PaperSim — 맨 아래 추가

```hlsl
OutPos = InPos;
OutVel = InVel;
OutVel.z = InVel.z - (Gravity * DeltaTime);
OutPos += OutVel * DeltaTime;

float floorZ = FloorHit ? FloorPos.z : -100000.0f;

float restHeight = floorZ + FloorLift;

float airborne = step(restHeight, OutPos.z);
OutPos.z = max(restHeight, OutPos.z);
OutVel *= airborne;

Landed = 1.0f - airborne;

float  hitF      = FloorHit ? 1.0f : 0.0f;
float3 fallbackN = float3(0.0f, 0.0f, 1.0f);
OutFloorN = lerp(fallbackN, FloorNrm, hitF);
```

| 핀 | 쪽 | 연결 |
|---|---|---|
| `FloorNrm` (Vector) | 왼쪽(입력) | Perform Collision Query Sync CPU의 법선 출력 |
| `OutFloorN` (Vector) | 오른쪽(출력) | Map Set `PARTICLES FloorN (Vector)` |

### PaperAero — settle 부분

```hlsl
float air = 1.0f - Landed;
float  faceSign = step(0.0f, dot(N, FloorN)) * 2.0f - 1.0f;
float3 flatN    = FloorN * faceSign;
float3 settle = cross(N, flatN) * SettleSpeed;
OutAngVel = (AngVel + torque * DeltaTime) * keepSpin * air + settle * Landed;
```

| 핀 | 쪽 | 연결 |
|---|---|---|
| `FloorN` (Vector) | 왼쪽(입력) | Map Get `PARTICLES FloorN` |

### 모듈별 쓰기 / 읽기

| 값 | Particle Spawn (Set) | PaperAero (위) | PaperSim (아래) | Dynamic Material Parameters (맨 아래) |
|---|---|---|---|---|
| `PARTICLES PaperBend (float)` | 쓰기 (−1~1 랜덤) | | | 읽기 |
| `PARTICLES FloorN (Vector)` | 쓰기 (0,0,1) | 읽기 | 쓰기 | |
| `PARTICLES Landed (float)` | | 읽기 | 쓰기 | 읽기 |

## 티키타카 — 질문하고 배운 것

### Q. 종이가 판때기 하나로 펄럭이는 건 종이가 아니잖아. 구현 가능한가?

- "단면"은 한쪽 면만 보이는 문제가 아니라 **판이 안 휘는** 문제였다. Claude가 처음에 두 뜻을 섞어 물음
- 가능. 머티리얼 WPO로 겉모습만 휜다. 판정은 평평한 판 그대로라 지금까지 만든 걸 안 깸

### Q. 너 영상 분석했던 거… 세션 새로 시작해서 모르는구나?

- 기록에 남은 건 바닥 하강·낙하 2.5초·몸 반응뿐이었고, **휘는 모양은 어디에도 없었다**(공기저항 노트는 오히려 "휘지 않는 판" 가정)
- 다시 분석하고, 이번엔 결과를 메모리에 남김

### Q. 접힌 건 하지 말자. 이러다 매일 종이만 구현하겠어

- V 접힘 제외, C·U 휨만. 그리고 "최소판(종이마다 랜덤 고정 휨)"으로 끝내는 선을 먼저 그음

### Q. SM_Paper1 Approx Size는 29×21 인데?

- Claude가 작은 스크린샷의 29를 20으로 잘못 읽고 "거의 정사각형"이라고 경고했다. 작업자가 확대해서 잡아냄 → **값으로 확인하는 습관이 Claude의 실수도 잡는다**

### Q. TexCoord가 뭐야, 어딨는 건데

- 점(꼭짓점)마다 붙은 "판의 어디쯤인가" 번호표(UV). 휘려면 점마다 가운데인지 끝인지 알아야 해서 빌려 씀
- 확인: Mask(R)을 Base Color에 임시로 꽂아 그라데이션이 **긴 쪽**을 따라가는 것을 봄 → R 사용
- Claude가 처음 띄운 그림 위젯은 이름 충돌(`top`)로 안 그려졌다

### Q. 이거 클라 프로그래머가 하는 거 맞나?

- 보통은 TA·VFX 영역 (커뮤니티 표준, 회사마다 다름)
- 클라에게 남는 건 협업 언어, 같은 벡터 수학, 디버깅 → **B(최소판 3단계까지 완주 후 멈춤)** 로 결정

### Q. 3단계를 하면 바닥에 닿으면 U·n자로 눕는 거야?

- 반대. 3단계는 바닥에서 휨을 **끈다**. `1 − Landed`가 바닥에서 0

### Q. 기울기에 따라 기울어서 바닥에 붙어 있나?

- 아니다. 휨(머티리얼)과 눕는 각도(PaperAero settle)는 다른 부분

### Q. 결국 종이 중점 기반으로 누울 수밖에 없는 거지? 절벽에 절반 걸치면 절반만 축 처지잖아

- **힌트 없이 작업자가 스스로 짚은 한계.** 경사면은 종이 밑 바닥이 어디나 같아서 중심 한 점이면 충분하지만, 절벽 끝은 중심 한 점으로는 바닥이 끊긴 걸 모른다
- 절벽 끝 처짐은 여러 점 측정 + 한쪽만 휘기가 필요 → 디테일 후보

### Q. flatN이 특정 값으로 고정된 건 아니지 않나? 계산 결과인데

- 맞다. 다만 계산되는 건 **부호(위/아래)뿐**이고 축은 월드 Z 고정 → 그래서 경사면에서도 항상 수평으로 누움

### Q. 바닥의 법선 벡터를 넣으면 된다는 건가?

- 맞았다. 다만 작업자 말: **"그것도 사실상 너 자동완성 본 거야"** — 앱 입력창의 추천 답장(Prompt suggestions, Tab)이 Claude의 힌트 많은 질문을 읽고 답을 미리 채워 줬다
- Claude 쪽 원인: 질문에 답의 모양을 너무 많이 넣었음 → 앞으로 힌트 없이 먼저 묻고, 막히면 한 칸씩

### Q. faceSign이 뭘 하는지 모르겠다 / M_Paper 노드도 왜 이렇게 구성됐는지 모르겠다. 그냥 따라 하는 느낌

- 판단·가설은 작업자가, "어떻게 계산하나"는 Claude가 했다 → 빈 곳은 **"어떻게"**
- 머티리얼 노드는 낯선 그림이 아니라 HLSL 다섯 줄 ([종이 휨](../paper-bend.md))
- 오늘 코드는 패턴 6개의 조합: ① ×(0/1) 끄기 ② ×2−1 ③ lerp로 고르기 ④ dot 같은 쪽인가 ⑤ cross 경첩 축 ⑥ 방향 × 길이

### Q. GameMathLab에서 내적·외적을 했는데도 왜 이해가 안 될까

- 시야각에서 쓴 내적은 "얼마나 같은가(정도)", faceSign은 "앞이냐 뒤냐(부호)". 이 쓰임은 연습 2(앞뒤좌우)였는데 건너뜀
- 더 큰 이유: faceSign이 **막는 문제(뒷면으로 떨어진 종이의 공중제비)를 본 적이 없다**. 질문을 가져 본 적 없는 답은 이해가 안 된다
- 그리고 한 줄에 내적 → step → ×2−1 → ×벡터 네 단계가 묶여 있음
- 덧붙임(일지 쓰며 발견): 10-29 [꼬챙이 노트](../../game-math/torque-skewer.md)의 "꼬챙이를 앞뒤 어느 쪽으로 꽂을지는 내적의 부호"가 faceSign과 **같은 것**이다. 배운 적은 있는데 모양이 바뀌니 못 알아본 것 → 성장 단계 ④(알아보기)의 연습거리

### Q. (망가뜨려 보기) flatN = FloorN 으로 했는데 뭐가 문제인지 모르겠다

- 발로 차도, TiltDeg를 바꿔도 차이를 못 봄. 이유: **우리 종이는 앞뒷면이 같은 색**이라 뒤집혀도 결과가 같아 보인다
- Claude가 "이 실험에서 뭐가 보일지"를 먼저 검증하지 않아 세 번 헛걸음. 위치(TiltDeg가 어디 있는지)도 안 알려 줌
- 정리: faceSign = "뒷면으로 떨어지면 뒷면인 채로 눕게 해서 공중제비를 막는 줄". 이 프로젝트에선 거의 티가 안 난다

### Q. 외적으로 축을 정하고, 어느 쪽으로 돌릴지는 faceSign으로 정한다?

- **맞다. 작업자 말로 나온 설명.** `cross(N, FloorN × s) = s × cross(N, FloorN)` 이라 코드와 같은 뜻
- 다듬은 한 문장: "종이 법선과 바닥 법선을 외적해서 돌릴 축을 정하고, faceSign(내적의 부호)으로 앞면·뒷면 중 덜 도는 쪽으로 방향을 정한다"

### Q. 그럼 얼만큼 회전시키는 건 settle에 있나?

- 외적의 **길이**가 빠르기다. 벌어질수록 길고, 평행하면 0 → 다 누우면 저절로 멈춘다 (`if` 필요 없음)
- 실제로 도는 양은 그 속도 × DeltaTime (쿼터니언 누적 줄) — 거속시

### Q. 어디까지 이해해야 할까

- 1층(그 줄이 무엇을 하나, 고칠 곳을 찾을 수 있나)은 꼭 / 2층(패턴)은 반복해서 만나며 천천히 / 3층(공식이 왜 그렇게 생겼나)은 궁금할 때만 (취향 · 바꿔도 됨)

- **한 칸 아래 기초**: `(u − 0.5) × 2` 일차함수(중2), `c²` 포물선(중3), 외적 길이 = sin(고1 삼각함수 — "벌어질수록 길고 평행하면 0"까지만), 속도 × DeltaTime(거속시)
- **감정**: "그냥 따라 하고 있는 느낌, 갑갑하다". 빈 곳은 판단이 아니라 "어떻게 계산하나"라는 진단
