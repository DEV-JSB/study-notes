### `PaperSim` (Particle Update, `PaperAero` 아래)

**`Custom Hlsl 001` — 선 시작·끝점 (새 노드)**

```hlsl
Start = Pos + float3(0.0f, 0.0f, 50.0f);      // 내 위치 50cm 위에서
End   = Pos - float3(0.0f, 0.0f, 10000.0f);   // 100m 아래까지
```

**기존 Custom HLSL — 이동·착지**

```hlsl
OutPos = InPos;
OutVel = InVel;
OutVel.z = InVel.z - (Gravity * DeltaTime);
OutPos += OutVel * DeltaTime;

float floorZ = FloorHit ? FloorPos.z : -100000.0f;   // 맞았으면 맞은 높이, 못 맞혔으면 바닥 없음
float restHeight = floorZ + FloorLift;

float airborne = step(restHeight, OutPos.z);
OutPos.z = max(restHeight, OutPos.z);
OutVel *= airborne;

Landed = 1.0f - airborne;
```

| 노드 | 핀 | 연결 |
|---|---|---|
| Map Get | **INPUT** `FloorQuery` (Collision Query) | → Perform 노드 `CollisionQuery` |
| `Custom Hlsl 001` | 왼쪽(입력) `Pos` (Position) | ← Map Get **PARTICLES** `Position` |
| `Custom Hlsl 001` | 오른쪽(출력) `Start`, `End` (Position) | → Perform 노드 `TraceStartWorld`, `TraceEndWorld` |
| Perform Collision Query Sync CPU | `TraceChannel` | `PaperFloor` |
| 기존 Custom HLSL | 왼쪽(입력) `FloorHit` (bool) | ← Perform 노드 `CollisionValid` |
| 기존 Custom HLSL | 왼쪽(입력) `FloorPos` (Position) | ← Perform 노드 `CollisionPosWorld` |
| 기존 Custom HLSL | 오른쪽(출력) `Landed` (float) | → Map Set **PARTICLES** `Landed` |

- 지운 것: Map Get **INPUT** `FloorZ`, Custom HLSL 왼쪽(입력) `FloorZ`, USER `FloorZ`

### `PaperAero` (Particle Update, `PaperSim` 위) — 3-4 부분

```hlsl
// 3-4: 착지하면 눕기
float air = 1.0f - Landed;
float3 flatN = float3(0.0f, 0.0f, step(0.0f, N.z) * 2.0f - 1.0f);
float3 settle = cross(N, flatN) * SettleSpeed;
OutAngVel = (AngVel + torque * DeltaTime) * keepSpin * air + settle * Landed;
```

| 줄 | 하는 일 | 연산 |
|---|---|---|
| `air = 1 - Landed` | 공중 1, 바닥 0 | 숫자 뒤집기 |
| `flatN` | 누우면 바라볼 방향. 위를 보고 있으면 (0,0,1), 뒤집혀 있으면 (0,0,-1) — 가까운 쪽으로 눕힘 | `step`으로 고르기 |
| `cross(N, flatN)` | N을 flatN 쪽으로 넘어뜨릴 **경첩 축**. 많이 기울수록 길어서 빨리 넘어가고, 거의 누우면 짧아져 스르륵 멈춤 | 외적 (경첩 축) |
| `* air`, `* Landed` | 0 또는 1을 곱해 둘 중 하나만 남김 (`if` 없이 고르기) | 늘이고 줄이기 |
| `+` | 펄럭임 회전과 눕기 회전 중 남은 하나 | 이어 붙이기 |

- 추가 핀: Map Get **PARTICLES** `Landed` (float) → 왼쪽(입력) `Landed` (float), Map Get **INPUT** `SettleSpeed` (float) → 왼쪽(입력) `SettleSpeed` (float)

## 티키타카 — 질문하고 배운 것

### Q. 바닥에 닿자마자 보정이 일어나는 거지?

- 닿은 **다음 프레임**부터. `PaperAero`가 `PaperSim`보다 위라서 `Landed`를 한 프레임 늦게 읽음 (60fps면 0.016초)
- 지금은 종이 **한가운데**를 축으로 돎 → 넘어가는 동안 아래쪽 절반이 바닥에 살짝 묻힘. 실제 종이는 먼저 닿은 **모서리**를 축으로 넘어가고, 비스듬히 떨어진 만큼 조금 미끄러짐 → 5단계(다듬기) 후보

### Q. SettleSpeed를 높이면 더 빨리 평평해져?

- 맞음. 넘어가는 회전 속도에 곱하는 숫자. 25° 착지 기준 4 → 약 0.8초, 8 → 0.4초, 20 → 0.16초, 50 → 약 0.06초
- 너무 크면(60fps에서 대략 60 이상) 평평한 자리를 지나쳐 **떨림**. 8~20 추천

### Q. SettleSpeed 8로 했는데 차이를 모르겠어

- 원인: `PaperSim`의 Map Set에 **PARTICLES** `Landed`를 안 만들었음 → Custom HLSL이 계산한 값이 **아무 데도 저장 안 되고 버려짐** → `PaperAero`는 늘 `Landed` = 0(공중)으로 읽음
- C#으로 치면 함수가 return한 값을 아무 변수에도 안 받은 것
- Spreadsheet에서 `Landed` 열이 안 보였던 건 열이 **알파벳 순**이라 화면 왼쪽 밖에 있었기 때문

### Q. `Out_SettleSpeed … has no valid offset. Possibly uninitialized data being used` 에러가 뭐야?

- `Out_` = Custom HLSL **출력** 핀이라는 표시. `SettleSpeed`를 **오른쪽(출력)**에 만들었는데 코드가 그 핀에 값을 한 번도 안 넣어서 "초기화 안 된 데이터"
- 기준: 코드가 **읽기만** 하는 값은 왼쪽(입력), 코드가 `=`로 **값을 넣는** 값은 오른쪽(출력)
- `Particle Spawn Script Interpolated`에도 같은 에러가 찍히는 건 Interpolated Spawning 때문. 원인은 하나

### Q. `float3(0,0f, 0.0f, …)` 뭘 잘못 쓴 거지?

- 점(`.`) 자리에 쉼표(`,`) → `0,0f`가 두 칸으로 읽혀 `float3`에 4칸을 넣은 셈. `0f`도 HLSL에서 안 되는 표기 (`0.0f`)
- HLSL 컴파일 에러의 절반은 쉼표·점·괄호 오타. 그 줄에서 개수부터 세기

### Q. FloorZ는 스폰할 때 저장한 거라, 높은 바닥 위로 가면 낮은 바닥까지 떨어지는 거 아냐?

- **시간**으로는 아니었음: `PaperSim`은 Particle Update라 USER `FloorZ`를 매 프레임 새로 읽음. 스폰 때 저장하는 건 `FloorLift`뿐
  - Particle Spawn 모듈 = 태어날 때 한 번 (`Start()`), Particle Update 모듈 = 매 프레임 (`Update()`)
- **위치**로는 맞는 걱정: `FloorZ`는 150장 전부가 쓰는 **숫자 하나** = "끝없이 평평한 판 하나". 더 높은 바닥(단상, 큐브) 위에서도 그걸 모르고 뚫고 내려감

### Q. 바닥이 "나 이만큼 내려갈 거야" 하고 종이한테 알려 주는 게 맞아?

- **판정: 종이가 스스로 느끼는 게 맞다.** 알려 주기는 계산이 싸서 고른 지름길이었음
  1. 바닥이 진짜 물체(메시·충돌 있음) → 엔진에 파티클이 지형을 느끼는 기능이 이미 있음 (Epic 공식)
  2. **의존 방향**: 바닥은 위에 뭐가 놓이는지 몰라야 함. 알려 주기 방식이면 바닥 BP가 종이를 붙잡고 있어야 하고, 다른 게 생길 때마다 챙길 게 늘어남
  3. 숫자 하나는 평평한 판 하나만 표현 가능
- 알려 주기가 맞는 경우: 실제 물체가 없는 값 (연출 타이밍, 가상의 수면 높이)
- 기본 Collision 모듈은 멈추기·튕기기까지 해서 `PaperSim`과 싸움 → **Collision Query로 바닥 높이만 재 오고** 착지 판단은 우리 코드 그대로

### Q. 검색해도 Collision Query가 목록에 없는데?

- 목록에 뜬 건 함수(완성된 처리). Collision Query는 **Data Interface** — 바깥 세계(씬)에 물어볼 수 있게 해 주는 **도구 핀**
- Map Get **+** 에서 INPUT으로 `Collision Query` 자료형을 만들고, 그 핀에서 선을 끌어 `Perform Collision Query Sync CPU`를 꺼냄
- Unity `Physics.Raycast`는 아무 데서나 부르지만, Niagara는 이 도구 핀을 먼저 쥐어야 함

### Q. 왜 Custom HLSL 노드를 새로 만들어?

- 선을 쏘려면 시작·끝점이 **먼저** 있어야 하고, 기존 노드는 쏜 **결과**로 착지를 판단함. 한 노드가 둘 다 하려면 출력이 Perform 노드를 거쳐 자기 입력으로 돌아와야 하는데 그래프는 **빙 돌아오는 연결이 안 됨**
- `MakeRay(pos)` → `Raycast(start, end)` → `Land(hit)` 처럼 차례로 부르는 것과 같음
- 3-2 때 `Custom Hlsl 001`은 실수였지만 이번엔 일부러 만든 것

### Q. FloorLift가 뭐였더라?

- 종이마다 바닥에서 **0.1~0.6cm 살짝 띄우는 높이**. 같은 높이에 겹치면 화면이 누가 앞인지 헷갈려 깜빡임(Z-파이팅)
- 스폰 때 정해서 PARTICLES에 기억 → 착지할 때도 `restHeight = 바닥 + FloorLift`

### Q. 왜 Niagara + Custom HLSL이야? 종이마다 BP나 C++ 컴포넌트로 짜면 안 좋아?

- 둘 다 정상적인 선택지. 기준은 **종이가 연출인가, 게임 오브젝트인가**

| | 종이마다 액터 | 관리자 액터 1개 + C++ + ISM | Niagara (지금) |
|---|---|---|---|
| 계산 | 150장은 버팀, 수천 장이면 무거움 | 빠름 | 빠름, GPU로 옮기면 수만 장 |
| 디버깅 | 브레이크포인트 됨 | 됨 | 어려움 (Spreadsheet로 값만) |
| 게임플레이와 엮기 | 제일 쉬움 | 쉬움 | 어려움 |

- 영상의 종이는 **연출** → Niagara 유지. 종이를 줍는 기능 같은 게 생기면 그 종이만 액터로
- Custom HLSL을 쓰는 건 `vn = dot(Vel, N) * N` 한 줄이 노드로는 4~5개라서 (취향 · 바꿔도 됨)

### Q. Custom HLSL은 셰이더 코드 아냐? 어떻게 Update처럼 돼?

- HLSL은 **언어 이름**. Niagara가 그래프 전체를 HLSL로 합친 뒤, CPU 시뮬레이션이면 **Vector VM**으로 CPU에서 실행 (GPU 시뮬레이션이면 컴퓨트 셰이더)
- Particle Update = Niagara가 매 프레임 `foreach (파티클) { Map Get → 우리 코드 → Map Set }`

| 컴포넌트 Update | Niagara |
|---|---|
| 멤버 변수 | PARTICLES 칸 |
| 매개변수 / 반환값 | Custom HLSL 왼쪽(입력) / 오른쪽(출력) |
| `Start()` | Particle Spawn |
| 엔진 함수 호출 | Data Interface를 통해서만 |

- 다른 점: 객체가 아니라 표의 한 줄, 모든 종이가 같은 코드(차이는 값으로), `if` 제한, 브레이크포인트 없음

### Q. 오늘 HLSL을 게임 개발자로서 어디까지 이해해야 해?

| 층 | 범위 | 오늘 코드에서 |
|---|---|---|
| 1층: 직접 다시 쓸 수 있어야 | 속도·위치 갱신, 내적 부호와 크기, **속도 쪼개기(vn/vt)**, `x * max(0, 1 - k*dt)` 감쇠, `step`/`lerp`/`clamp` | 경사면 미끄러짐·벽 타기·마찰·시야각에서 그대로 다시 나옴 |
| 2층: 읽고 말할 수 있으면 | 외적 = 두 방향에 수직인 축(순서 바꾸면 반대, 길이 = 벌어진 정도), `torque = dot * cross`, 각속도 = 축 × 속도 | `cross(N, flatN)`, `torque` |
| 3층: 블랙박스 OK | 쿼터니언으로 방향 돌리기·회전 누적·각도로 쿼터니언 만들기 | UE C++에선 `Q.RotateVector`, `FQuat(Axis, Angle) * Q`, `FQuat(FRotator)` |

## 🚨 오늘 걸린 함정 (습관 경보)

- **입력 핀을 오른쪽(출력)에 만듦** → `Out_SettleSpeed … uninitialized` 컴파일 에러. 핀 방향은 "코드가 읽나, 쓰나"로
- **Map Set에 `Landed`를 안 만듦** → 계산한 값이 저장 안 돼서 늘 0. 모듈끼리 주고받는 값은 쓰는 쪽 Map Set + 읽는 쪽 Map Get, 둘 다 **PARTICLES**
- **`float3(0,0f, …)` 오타** → 쉼표 하나로 칸 수가 바뀜
- **bool 이름 규칙**: 언리얼 C++의 `b` 접두사(`bIsLanded`)는 bool 자료형용 (Epic 공식). `Landed`는 곱셈에 쓰는 0/1 **float**라 `b`를 안 붙임
- **트레이스 채널 `WorldStatic`** → 캐릭터 캡슐도 막혀서 종이가 머리 위에 얹힘. 용도별 **전용 트레이스 채널**을 만드는 게 표준 (Epic 공식). 기존 채널에서 캐릭터를 빼면 벽 판정까지 망가질 수 있음
- **Claude 안내 실수 (규약으로 고침)**
  - 핀 태그(PARTICLES/INPUT)와 왼쪽/오른쪽을 안 적음 → 이제 매번 **태그 + 이름 + 자료형 + 왼쪽/오른쪽** 전부 적기로 (`CLAUDE.md` §2.2)
  - "Lifetime 5라서 종이가 사라질 수 있다"고 잘못 경고 → 1단계에서 Particle State kill을 꺼 둠. 사라지지 않음
  - "바닥이 USER 값으로 알려 주기"를 추천했다가 작업자 지적으로 "종이가 느끼기"로 바꿈
