- C#으로 치면 함수 매개변수. 매개변수로 안 받은 변수는 함수 안에서 못 씀

### Q. Module. / User. / Engine. 이런 건 무슨 기준이야? User.이 없는데 만들어야 해?

- 앞에 붙는 건 **"이 값이 어디 사는가"(Namespace)**

| 화면 표시 | 누가 쓰나 | 예 |
|---|---|---|
| ENGINE | 엔진이 채워줌, 읽기 전용 | DeltaTime |
| PARTICLES | 파티클마다 한 칸, 같은 이미터 모듈끼리 공유 | Position, Velocity, FloorLift |
| INPUT | 이 모듈의 입력칸. **스택 Details에 입력 상자로 나타남** | Gravity, FloorZ |
| USER | **바깥(BP, 레벨)에서** 넣는 값 | User.FloorZ |
| SYSTEM / EMITTER | 시스템·이미터 단위 값 | — |

- Map Get 메뉴에 USER가 안 보이는 게 정상. **표준 패턴 [B]: 모듈은 INPUT으로 받고, 스택 Details에서 ▼ → Link Inputs → User → FloorZ로 연결**
- 이렇게 하면 모듈은 "값이 어디서 오는지" 몰라도 됨 → 나중에 BP가 값을 넣어도 모듈 코드는 그대로

### Q. 그럼 INPUT이라고 하지 왜 Module이라고 해?

- 내부 이름은 `Module.`이지만 화면 태그는 **INPUT**. 설명은 **화면에 보이는 이름**으로 하기로 함

### Q. FloorLift는 PaperSpawnInit에만 만들었는데?

- **PARTICLES 값은 이미터 안 모든 모듈이 공유하는 칸.** Spawn에서 Map Set으로 써 두면 Update의 `PaperSim`에서 Map Get으로 그대로 읽을 수 있음
- Unity로 치면 파티클 하나에 붙은 public 필드. Spawn에서 쓰고 Update에서 읽음

### Q. Custom HLSL은 셰이더 코드 아냐? 우리가 짠 건 그냥 Update 문 같은데

- 맞게 본 것. Particle Update에 둔 Custom HLSL은 **파티클 한 장마다, 매 프레임 도는 `Update()`**
- 언어가 HLSL일 뿐 화면에 그림을 그리는 셰이더가 아님. CPUSim이라 실제로는 CPU(Vector VM)에서 돎

## 직접 짠 코드 — `PaperSim`

```hlsl
OutPos = InPos;
OutVel = InVel;
OutVel.z = InVel.z - (Gravity * DeltaTime);     // 중력: 속도를 줄임
OutPos += OutVel * DeltaTime;                   // 속도만큼 이동
float restHeight = FloorZ + FloorLift;          // 이 종이가 누울 높이

float airborne = step(restHeight, OutPos.z);    // 공중이면 1, 바닥 아래면 0
OutPos.z = max(restHeight, OutPos.z);           // 바닥 아래로 못 내려가게
OutVel *= airborne;                             // 바닥이면 속도 0
```

- **규칙: 입력(In~)은 건드리지 않고, 먼저 Out에 복사한 뒤 Out만 고친다**
- 순서가 중요: 속도 갱신 → 위치 갱신 → 바닥 검사
- `restHeight`에 `FloorLift`를 더해야 1단계에서 띄운 높이(Z-파이팅 방지)가 착지 후에도 유지됨

## 🚨 오늘 걸린 함정 (습관 경보)

- **Position 핀을 Vector(노랑)로 만듦** → Position은 목록에서 **Position(분홍)**을 골라야 함. 핀 색 = 타입
- **Gravity 핀을 SYSTEM으로 만듦** → 스택에서 값을 넣을 입력칸은 **INPUT**
- **처음엔 `User.FloorZ`를 Map Get에서 바로 읽으라고 안내받음** → INPUT + 스택 Link가 표준 패턴으로 정정됨
- **입력값(InPos/InVel)을 직접 고침, 위치 갱신 빠뜨림, 비교 대상·조건 방향 틀림, else 잘못 씀** → 빈칸 채우기 뼈대로 다시 짬
- **C# 습관이 또 나옴**: `Vector3.zero` / `Vector(0,0,0)` → `float3(0,0,0)`, `1f` → `1.0f`
- **`if` 안에서 벡터 대입 → 컴파일 에러** (아래 "경험" 참고)

## 경험 — 왜 컴파일이 안 됐나 (Niagara CPU의 if 제한)

- 증상: 코드는 문법상 맞는데 에러
  - `if (...) { OutPos.z = h; }` → `Component x of variable branch_flatten_temp has no valid offset`
  - 벡터를 통째로 대입해도 → `Component x/y/z of variable vec_ctor has no valid offset`
- 원인: CPUSim은 **Vector VM**이 실행함. VM은 `if`를 "양쪽 다 계산하고 하나 고르기"로 펴서(flatten) 처리하는데, 그 과정의 임시 벡터를 처리 못 함
- 해결: **분기 없이 수학으로 고르기**
  - `step(edge, x)` = `x >= edge ? 1 : 0` → 공중/바닥을 0과 1로
  - `max(a, b)` → 바닥보다 아래로 못 가게
  - 값 × 0 또는 1 → 조건부로 끄기
- 교훈: **Niagara CPU Custom HLSL에서는 처음부터 if 대신 step / max / lerp로 짠다.** 에러 메시지의 `branch_flatten`이 힌트
- 덤: Interpolated Spawning이 켜져 있으면 같은 에러가 "Particle Spawn Script Interpolated"에도 한 번 더 찍힘. 원인은 하나
