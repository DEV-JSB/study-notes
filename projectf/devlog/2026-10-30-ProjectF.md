## 최종 코드

### `PaperToucherComponent.h` (핵심)

```cpp
UCLASS(ClassGroup = (PaperFX), meta = (BlueprintSpawnableComponent))
class PROJECTF_API UPaperToucherComponent : public UActorComponent
{
	GENERATED_BODY()

public:
	UPaperToucherComponent();

public:
	UPROPERTY(EditAnywhere, Category = "PaperToucher")
	FName BoneName = TEXT("foot_l");
	UPROPERTY(EditAnywhere, Category = "PaperToucher")
	float TouchRadius = 15.f;
	UPROPERTY(EditAnywhere, Category = "PaperToucher")
	bool bDrawDebug = true;

	UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "PaperToucher")
	FVector PartPos = FVector::ZeroVector;
	UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "PaperToucher")
	FVector PartVel = FVector::ZeroVector;

private:
	UPROPERTY()
	TObjectPtr<USkeletalMeshComponent> OwnerMesh;

	FVector PrevPartPos = FVector::ZeroVector;

protected:
	virtual void BeginPlay() override;

public:
	virtual void TickComponent(float DeltaTime, ELevelTick TickType, FActorComponentTickFunction* ThisTickFunction) override;
};
```

### `PaperToucherComponent.cpp` (핵심)

```cpp
void UPaperToucherComponent::BeginPlay()
{
	Super::BeginPlay();

	ACharacter* OwnerCharacter = Cast<ACharacter>(GetOwner());
	if (!IsValid(OwnerCharacter))
	{
		UE_LOG(LogTemp, Warning, TEXT("%s: owner is not a Character"), *GetName());
		SetComponentTickEnabled(false);
		return;
	}

	OwnerMesh = OwnerCharacter->GetMesh();
	if (!IsValid(OwnerMesh) || !OwnerMesh->DoesSocketExist(BoneName))
	{
		UE_LOG(LogTemp, Warning, TEXT("%s: bone '%s' not found"), *GetName(), *BoneName.ToString());
		SetComponentTickEnabled(false);
		return;
	}

	PartPos = OwnerMesh->GetSocketLocation(BoneName);
	PrevPartPos = PartPos;
}

void UPaperToucherComponent::TickComponent(float DeltaTime, ELevelTick TickType, FActorComponentTickFunction* ThisTickFunction)
{
	Super::TickComponent(DeltaTime, TickType, ThisTickFunction);

	if (DeltaTime <= 0.f)
	{
		return;
	}

	PartPos = OwnerMesh->GetSocketLocation(BoneName);
	PartVel = (PartPos - PrevPartPos) / DeltaTime;
	PrevPartPos = PartPos;

	if (bDrawDebug)
	{
		DrawDebugSphere(GetWorld(), PartPos, TouchRadius, 12, FColor::Cyan);
		// + AddOnScreenDebugMessage(GetUniqueID(), …, speed = PartVel.Size())
	}
}
```

### `BP_PaperField` Event Graph

```
BeginPlay → Get Player Character (0) → Get Component By Class (PaperToucherComponent) → SET Toucher
Tick      → Is Valid (Toucher) → Set Niagara Variable (Position) FootPos = Toucher.PartPos
                               → Set Niagara Variable (Vector3)  FootVel = Toucher.PartVel
```

### `PaperInfluence` (새 스크래치 모듈, Particle Update 맨 위)

```hlsl
float dist = length(FootPos - Pos);
float inside = step(dist, FootRadius);
float footSpeed = length(FootVel);
float moving = clamp(footSpeed / WakeSpeed, 0.0f, 1.0f);
float w = inside * moving;
float3 kick = FootVel * PushStrength + float3(0.0f, 0.0f, 1.0f) * footSpeed * LiftStrength;
OutVel = lerp(Vel, kick, w);
Touched = w;
```

| Map Get (기존 노드) | → Custom HLSL (새 노드) 왼쪽 | 값 |
|---|---|---|
| `PARTICLES Position (Position)` | `Pos (Position)` | |
| `PARTICLES Velocity (Vector)` | `Vel (Vector)` | |
| `INPUT FootPos (Position)` | `FootPos (Position)` | 스택에서 User.FootPos에 Link |
| `INPUT FootVel (Vector)` | `FootVel (Vector)` | 스택에서 User.FootVel에 Link |
| `INPUT FootRadius (float)` | `FootRadius (float)` | 20 |
| `INPUT PushStrength (float)` | `PushStrength (float)` | 0.5 |
| `INPUT LiftStrength (float)` | `LiftStrength (float)` | 0.6 |
| `INPUT WakeSpeed (float)` | `WakeSpeed (float)` | 100 |

| Custom HLSL 오른쪽 | → Map Set (기존 노드) |
|---|---|
| `OutVel (Vector)` | `PARTICLES Velocity (Vector)` |
| `Touched (float)` | `PARTICLES Touched (float)` (새 속성, 확인용) |

## 티키타카 — 질문하고 배운 것

### Q. 발목 뼈가 바닥에서 살짝 떠 있는데 괜찮나?

- 괜찮다. 단 반지름 > 발목 높이(8.7cm). 바닥에서 닿는 폭 = 2 × √(반지름² − 높이²)

### Q. 영상 분석으로 보면 속도 방향은 뭐가 어울릴까?

- 기준 두 개(서 있으면 반응 없음 / 휘두른 발이 지나간 종이만 일어섬)로 후보 셋을 표로 대 봄 → **② 발 방향 + 위쪽, 위쪽도 발 빠르기에 비례**

### Q. 캐릭터 BP에서 하면 한 명만 탐지되는 거 아냐?

- 맞다. 조작 가능한 캐릭터가 3명(같은 클래스) → 발 계산은 **컴포넌트**로, 값을 모으는 건 **종이 쪽(BP_PaperField)**. 4-1a는 1명, 4-1b에서 6개

### Q. C++로 안 만들고 BP로 만들어?

- 처음 BP로 안내한 건 흐름을 따랐을 뿐 따져 본 게 아니었음 → 재사용 부품이라 **C++** (Epic 공식 권장)

### Q. UPROPERTY + TObjectPtr 규칙은 왜 생겼어? / FName이랑 FString은 왜 나뉘어?

- `UPROPERTY()`: 언리얼 자체 GC는 표시된 포인터만 봄. 없으면 지워진 메모리를 가리켜 가끔 크래시
- `TObjectPtr`: UE5 멤버 포인터. 에디터에서는 로딩 추적, 배포 빌드에서는 맨 포인터와 같음
- FName = 이름 표 번호(비교 빠름, 대소문자 무시, 수정 불가) / FString = 글자 편집 / FText = 화면용 번역 글자. 유니티 `Animator.StringToHash`와 같은 이유

### Q. 계속 달리는데 Details 값이 안 바뀌어

- 가설 셋(서 있어서 / Details 화면 갱신 안 됨 / Tick이 한 번만) → 다른 액터를 눌렀다 다시 선택하니 갱신 → **화면 문제였음**

### Q. USER 네임스페이스가 없는데 새로 만들어? / 입력이 안 보여

- 모듈은 **INPUT**으로 받고 스택에서 **User에 Link** (2단계 FloorZ와 같은 방식, 4-1b와 이어짐)
- 입력이 스택에 안 보인 건 Custom HLSL이 아직 없어서 **안 쓰이는 입력을 Niagara가 버림**

### Q. 일부만 움직이고 대부분 반응을 안 해

- 가설 ① 구가 작다 ② 디딘 발은 멈춰 있고 빠른 발은 공중 ③ NormalDrag → 하나씩 바꿔 ①로 확인 (15 → 20: 바닥 폭 24 → 36cm)
- 반지름을 키우니 **잘 떠오름** → ③은 문제 아님

### Q. HLSL을 다 이해 못 했어 / Touched는? / LiftRatio가 뭐야?

- 같은 계산을 C++로 옮겨 봄 → 노트로 정리: [발에 반응하는 종이](../paper-influence.md)
- 깨달은 문장: **"발로 찬 만큼 앞과 위로 각자 곱하는 거구나. 500을 찼으면 250은 앞으로, 250은 위로 해서 45도로 튀는 것처럼"** → 맞음 (나누는 게 아니라 각자, 그래서 둘 다 1이면 더 세짐)
- 작업자 의심: `footSpeed`는 관련 없는 것 같다 → 빼면 위쪽이 늘 0.6cm/s라 안 뜸 (방향 × 크기 × 비율)
- 작업자 지적: "LiftStrength여야 하지 않나" → 맞음, 짝이 안 맞는 이름이었음 → `PushStrength` / `LiftStrength`

## 🚨 오늘 걸린 함정 (습관 경보)

- **`MateCharacter.h`의 `ACharacter* Leader;`** — 다른 액터를 가리키는 멤버에 `UPROPERTY()`가 없음. 리더가 Destroy되면 `FollowLeader`에서 크래시(GC 후에만 터져 재현 어려움) → `TWeakObjectPtr<ACharacter>` + `IsValid` (Epic 공식). **아직 안 고침**
- **BP 변수 기본 자료형** — `Toucher`가 Boolean으로 만들어져 있었음 → Variable Type에서 Paper Toucher Component (Object Reference)
- **Niagara 파라미터 자료형 충돌** — `This variable already exists with a different type` → 같은 이름을 Position으로 다시 만들려 함. FootVel은 Vector
- **Map Set에서 USER/INPUT을 찾음** — Map Set은 쓰는 노드라 읽기 전용 태그가 안 나옴
- **Claude 실수**
  - 컴포넌트를 처음에 따져 보지 않고 BP로 안내, 접두사도 `BPC_`로 잘못 말함 (Allar 규칙은 `BP_…Component`, C++는 `U…`)
  - `KickStrength` / `LiftRatio`로 짝이 안 맞는 이름을 지음 → 작업자가 잡음
  - 답 하나를 영어로 씀
