PaperAero 한 장 지도

종이가 종이처럼 떨어지게 만드는 모듈 하나를 21줄이 아니라 4덩어리로 읽습니다. 덩어리마다 한 문장, 그림, 코드, 줄별 뜻, 어디까지 알아야 하는지, 직접 해 볼 실험을 붙였습니다.

매 프레임 종이 한 장마다: 어느 쪽을 보나 구하고 → 공기가 속도를 깎고 → 얼마나 돌지 정하고 → 그만큼 돌린다.

1

방향 구하기

블랙박스 OK

회전값 Q를 써서, 원래 위(0,0,1)를 보던 종이가 지금 어느 쪽을 보는지(N) 구한다.

// 3-1: 법선
float3 up = float3(0, 0, 1);
float3 t  = 2.0f * cross(Q.xyz, up);
N = up + Q.w * t + cross(Q.xyz, t);

세 줄 전체가 "벡터 up을 쿼터니언 Q로 돌린다"는 공식 하나입니다. HLSL에 함수가 없어서 손으로 풀어 쓴 것뿐입니다.

알아야 할 것"회전값으로 종이가 보는 방향을 구했다." 이 한 줄이면 충분합니다. 몰라도 되는 것t = 2 * cross(…)가 왜 이런 모양인지. UE C++에선Q.GetUpVector() 또는 Q.RotateVector(FVector::UpVector) 한 줄. Unity에선transform.up 또는 q * Vector3.up.
2

공기저항

이해함

속도를 면을 뚫는 쪽과 면을 따라가는 쪽으로 쪼개고, 뚫는 쪽은 많이 비탈 쪽은 조금 깎은 뒤 다시 이어 붙인다. 그래서 종이가 비스듬히 미끄러진다.

// 3-2: 판 공기저항
float3 vn = dot(Vel, N) * N;
float3 vt = Vel - vn;
float keepN = max(0.0f, 1.0f - NormalDrag * DeltaTime);
float keepT = max(0.0f, 1.0f - PlaneDrag  * DeltaTime);
OutVel = vn * keepN + vt * keepT;
줄하는 일연산
dot(Vel, N)Vel이 N 쪽으로 몇 cm/s인가 (그림자 길이, 숫자 하나)그림자 (내적)
… * N그 숫자를 N 방향 화살표로 = vn늘이고 줄이기
Vel - vn남은 조각 = vt, 면과 나란함떼어내기
max(0, 1 - Drag * dt)이번 프레임에 남길 비율. 음수가 되어 속도가 뒤집히는 것만 막음숫자 계산
vn*keepN + vt*keepT따로 깎은 두 조각을 다시 이어 붙임늘이고 줄이기 → 이어 붙이기
알아야 할 것이 다섯 줄 전부. 경사면 미끄러짐, 벽 타고 미끄러지기, 마찰에서 그대로 다시 나옵니다 (연습 3번). 더 보기판 공기저항 노트, 벡터 더하기·빼기·곱하기
3

회전 속도

torque 한 줄 남음

종이가 얼마나 빨리, 어느 축으로 돌지(회전 속도)를 정한다. 공중이면 바람이 비트는 만큼 돌고, 바닥이면 평평한 쪽으로 넘어간다.

// 3-3: 공중 — 바람이 비트는 힘
float3 v = Vel * 0.01f;
float3 torque = dot(N, v) * cross(N, v) * FlipStrength;
float keepSpin = max(0.0f, 1.0f - SpinDrag * DeltaTime);

// 3-4: 바닥 — 평평한 쪽으로 넘어가기
float air = 1.0f - Landed;
float3 flatN = float3(0.0f, 0.0f, step(0.0f, N.z) * 2.0f - 1.0f);
float3 settle = cross(N, flatN) * SettleSpeed;

// 둘 중 하나 고르기
OutAngVel = (AngVel + torque * DeltaTime) * keepSpin * air + settle * Landed;

먼저 알아 둘 것: 회전 속도는 "축 화살표"

회전 속도(AngVel)도 화살표 하나입니다. 화살표 방향 = 도는 축, 화살표 길이 = 도는 빠르기. 위치에 속도가 있듯 회전에는 회전 속도가 있고, ④가 매 프레임 그만큼 돌려 줍니다. 그래서 ③은 회전값을 직접 건드리지 않고 회전 속도만 정합니다.

공중: 바람이 종이를 비튼다

줄하는 일연산
v = Vel * 0.01cm/s를 m/s로. 숫자가 너무 커지지 않게 줄여 둔 것늘이고 줄이기
dot(N, v)바람을 얼마나 정면으로 받나. 모서리로 가르면 0그림자 (내적)
cross(N, v)어느 경첩 축으로 비틀리나. 길이는 기울어진 정도경첩 축 (외적)
* FlipStrength비트는 세기 조절늘이고 줄이기
AngVel + torque * dt지금 회전 속도에 이번 프레임 비틀림을 더함이어 붙이기
* keepSpin회전에 거는 브레이크(SpinDrag). 없으면 영원히 돎늘이고 줄이기

왜 왔다 갔다(지그재그) 하나

순서일어나는 일담당
1종이가 기울어 있으면 비탈 쪽으로 미끄러진다②
2미끄러지면 움직이는 방향(v)이 바뀌고, 바람 방향도 바뀐다②
3종이는 새 바람을 정면으로 받으려고 돈다③ torque
4회전 속도가 남아 있어서 지나쳐 반대로 기운다③ AngVel이 이어짐
5반대쪽으로 미끄러진다 → 1로. SpinDrag가 조금씩 잦아들게 함② ③

줄 하나가 펄럭임을 만드는 게 아니라, ②와 ③이 매 프레임 서로 주고받는 고리가 펄럭임을 만듭니다.

바닥: 평평한 쪽으로 넘어간다

줄하는 일
air = 1 - Landed공중 1, 바닥 0
step(0, N.z)*2 - 1위를 보면 +1, 뒤집혀 있으면 −1. 가까운 쪽으로 눕힘
cross(N, flatN)N을 flatN 쪽으로 넘어뜨릴 경첩 축. 많이 기울수록 길어 빨리 돌고, 거의 누우면 짧아져 멈춤
* SettleSpeed넘어가는 빠르기
… * air + settle * Landed0이나 1을 곱해 둘 중 하나만 남김. if 대신
알아야 할 것회전 속도 = 축 화살표. 공중/바닥에 따라 넣는 회전 속도만 바꿔 끼운다. 0/1 곱해서 고르기. cross는 "경첩 축, 순서 바꾸면 반대". 말로 설명할 수 있으면 됨torque = dot × cross: "얼마나 정면으로 받나 × 어느 축으로 비틀리나". 성분 계산은 몰라도 됩니다. Unity에선rb.angularVelocity = Vector3.Cross(transform.up, Vector3.up) * strength; — 넘어진 물체 일으키기와 같은 수법

돌리기

블랙박스 OK

③에서 정한 회전 속도만큼, 이번 프레임 시간(DeltaTime)어치 종이를 돌린다.

// 회전값에 누적
float3 dq  = Q.w * OutAngVel + cross(OutAngVel, Q.xyz);
float  dqw = -dot(OutAngVel, Q.xyz);
OutQuat = normalize(Q + 0.5f * DeltaTime * float4(dq, dqw));

위치에서 Pos += Vel * dt를 하듯, 회전에서 "회전값 += 회전 속도 × dt"를 하는 것입니다. 쿼터니언이라 모양이 복잡할 뿐입니다. normalize는 계산 오차로 회전값이 찌그러지지 않게 크기를 1로 맞추는 줄.

알아야 할 것"회전 속도만큼 이번 프레임 분 돌린다." Vel → Pos와 같은 구조라는 것. 몰라도 되는 것0.5와 dq, dqw가 왜 이런 모양인지. UE C++에선FQuat Delta(축, 각도); NewQ = Delta * Q; Unity에선q = Quaternion.AngleAxis(각도, 축) * q;

같은 일을 UE C++로 쓰면

HLSL이라 낯선 부분이 UE C++ 함수로 바뀌면 어떻게 읽히는지 보는 용도입니다. ①과 ④가 한두 줄로 줄어듭니다. 연습 프로젝트에서 짜게 될 모양에 가깝습니다.

// 개념용 · 컴파일 확인 안 함
// ① 방향 구하기
const FVector N = Q.GetUpVector();

// ② 공기저항
const FVector Vn = FVector::DotProduct(Vel, N) * N;
const FVector Vt = Vel - Vn;
const float KeepN = FMath::Max(0.f, 1.f - NormalDrag * DeltaTime);
const float KeepT = FMath::Max(0.f, 1.f - PlaneDrag  * DeltaTime);
OutVel = Vn * KeepN + Vt * KeepT;

// ③ 회전 속도
if (bLanded)
{
    const FVector FlatN(0.f, 0.f, N.Z >= 0.f ? 1.f : -1.f);
    OutAngVel = FVector::CrossProduct(N, FlatN) * SettleSpeed;
}
else
{
    const FVector V = Vel * 0.01f;
    const FVector Torque = FVector::DotProduct(N, V) * FVector::CrossProduct(N, V) * FlipStrength;
    const float KeepSpin = FMath::Max(0.f, 1.f - SpinDrag * DeltaTime);
    OutAngVel = (AngVel + Torque * DeltaTime) * KeepSpin;
}

// ④ 돌리기
const float Speed = OutAngVel.Size();
if (Speed > KINDA_SMALL_NUMBER)
{
    const FQuat Delta(OutAngVel / Speed, Speed * DeltaTime);   // 축, 각도(라디안)
    OutQuat = (Delta * Q).GetNormalized();
}

C++에서는 if를 그냥 쓰면 됩니다. HLSL에서 air, Landed를 곱했던 건 Niagara CPU에서 if 안 벡터 대입이 안 되기 때문이었습니다.

어디까지 알면 되나

층범위이 지도에서
1층 · 직접 쓸 수 있어야속도 쪼개기, 감쇠 비율, 0/1 곱해서 고르기, "회전 속도 = 축 화살표"② 전체, ③의 바닥 쪽과 고르기
2층 · 말로 설명외적 = 경첩 축(순서 바꾸면 반대), torque = 정면 정도 × 비틀리는 축, 지그재그 고리③의 torque, settle
3층 · 블랙박스쿼터니언으로 방향 구하기, 회전 누적 공식①, ④

2층은 연습 프로젝트 2번(맞은 방향: 외적의 부호)과 4번(포탑 회전: 외적 + 쿼터니언)을 C++로 짜 보면서 손에 붙입니다. 그 뒤에 이 지도를 다시 보면 ③이 훨씬 쉽게 읽힐 겁니다.
