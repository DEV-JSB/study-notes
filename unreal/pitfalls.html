생성자에서 AddDynamic → 조용히 안 불림

증상
Overlap 함수 내용도 맞고 컴파일도 되는데, 타겟이 들어와도 로그가 안 뜬다
처음 의심
헤더를 Live Coding으로 반영해서 → 풀 빌드로 실험 → 그래도 안 됨 → 기각
원인
이벤트와 함수를 잇는 AddDynamic을 생성자에서 했다. 연결 정보가 BP 에셋(BP_Turret.uasset)에 같이 저장되고, 레벨에 놓인 터렛에서는 제대로 안 살아났다 (엔진 내부의 정확한 단계는 확실치 않음)
해결
BeginPlay로 한 줄 옮김 → 바로 로그가 떴다
// ✗ 생성자
ATurret::ATurret() { ... DetectSphere->OnComponentBeginOverlap.AddDynamic(this, &ATurret::OnSphereTriggerEnter); }

// ✓ BeginPlay
void ATurret::BeginPlay()
{
	Super::BeginPlay();
	DetectSphere->OnComponentBeginOverlap.AddDynamic(this, &ATurret::OnSphereTriggerEnter);
	DetectSphere->OnComponentEndOverlap.AddDynamic(this, &ATurret::OnSphereTriggerExit);
}

찾은 방법: 가설 하나에 실험 하나. 한 번에 여러 개를 고쳤다면 무엇이 원인인지 몰랐다. 막히면 양쪽(타겟 BP의 Event ActorBeginOverlap → Print String)에서 동시에 관찰해 ①과 ②를 가를 수도 있다.

헤더 변경과 Live Coding

증상
헤더에 UPROPERTY를 추가했는데 Details에 안 보인다. Output Log에 Live coding failed, data type changes may cause...
원인
마지막 진짜 빌드(UnrealEditor-GameMathLab.dll)보다 헤더가 나중에 바뀌었고, 반영은 Live Coding 패치(patch_N.exe)로만 됐다
해결
에디터를 끄고 IDE에서 Development Editor / Win64 빌드 → .dll 시간이 방금인지 확인
말출처
UE5 Live Coding은 재인스턴싱이 켜져 있으면 새 함수·변수 같은 큰 변경도 반영하려고 한다. 꺼져 있으면 예측 불가, 대개 크래시Epic 공식 문서
그래도 헤더(UPROPERTY / UFUNCTION / 새 클래스)를 바꾸면 끄고 빌드하는 게 안전하다커뮤니티 표준 (규칙 아님)
.cpp 함수 안쪽, .cpp의 #include 추가는 Live Coding으로 충분커뮤니티 표준

스스로 확인하는 법: 안 될 때는 Output Log를 위로 올려 빨강(Error)·노랑(Warning)부터. Binaries/Win64의 .dll과 patch_N.exe 시간을 소스 파일 시간과 비교.

"헤더 바꾸면 무조건 재시작"은 과장이었다. "확실해?"라고 물어서 Epic 문서로 바로잡음

생성자는 Details 값보다 먼저 돈다

증상
Details에서 DetectRadius를 바꿔도 구 크기가 그대로. DetectDeg를 바꿔도 판정 기준이 그대로
처음 의심
"생성자라서 float이 아직 초기화 안 됐다" → 아님. float X = 90.f;는 생성자 본문보다 먼저 들어간다
원인
늦게 오는 건 Details에서 바꾼 값이다
해결
Details 값을 쓰는 계산은 OnConstruction(에디터에서 값 바꿀 때마다) 또는 BeginPlay(게임 시작 때 한 번)
  • InitSphereRadius는 생성자 전용, 그 외엔 SetSphereRadius (겹침 상태까지 갱신)
  • 값은 한 곳에서만: 탐지 거리는 DetectRadius 하나, 구는 그걸 따라가기만

Epic 공식 (OnConstruction = C++ Construction Script) · DetectRadius에서 배우고 DetectCos에서 또 만남

FVector::ForwardVector는 언제나 (1, 0, 0)

증상
터렛은 도는데 원뿔 판정 방향은 한쪽에 고정
원인
GetTransform().GetLocation().ForwardVector — ForwardVector는 static 상수. C++은 static 멤버를 아무 벡터 뒤에 .으로 붙여도 컴파일되고, 앞의 값과 상관없이 월드 X축이 나온다
해결
GetActorForwardVector() / GetActorRightVector() / GetActorUpVector()

Epic 공식 · 같은 함정: FVector::RightVector(월드) vs GetActorRightVector()(터렛)

도·라디안·cos 섞기

증상
원뿔 판정이 정면·옆·뒤 전부 true, 또는 정면은 못 잡고 옆을 잡음
원인
내적 결과(cos 값, -1~1)를 도(45)와 비교 / cos 값을 라디안인 줄 알고 RadiansToDegrees / DegreesToRadians까지만 하고 Cos 빠뜨림 / 부등호 반대 / Abs로 뒤쪽을 앞쪽으로 바꿈
해결
DetectCos = FMath::Cos(FMath::DegreesToRadians(DetectDeg)); 후 DetectCos <= Result
함수받는 단위
FMath::Cos, FMath::Acos 결과, FQuat(Axis, Angle)라디안
V.RotateAngleAxis(AngleDeg, Axis), FRotator(Pitch, Yaw, Roll)도
FVector::DotProduct 결과 (길이 1끼리)각도 아님. cos 값

잡는 법: 손 계산 검증. 정면 1, 옆 0, 뒤 -1을 넣어 따라가기. 값은 두세 개 — 45°에서는 라디안 0.785와 cos 0.707이 우연히 비슷해서 버그가 숨는다. 처음 쓰는 함수는 매개변수 이름(AngleDeg)부터 확인. 자세한 그림은 레이더 원뿔 판정.

충돌: Preset ≠ Object Channel, 반응은 약한 쪽

증상
새로 만든 채널 Target이 Collision Presets 목록에 없다
원인
Preset은 "설정 묶음". Object Channel은 "나는 어떤 종류인가". Presets를 Custom...으로 바꾸면 나오는 Object Type 칸에 있다
  • Overlap은 양쪽 다 Generate Overlap Events가 켜져 있어야 한다
  • 이벤트는 게임이 돌 때만 일어난다. Play 전에 에디터에서 옮기면 안 일어남. Play 중 F8로 빠져나와 옮기면 일어남
  • C++에서는 채널을 번호로 부른다(ECC_GameTraceChannel1). 번호는 Config/DefaultEngine.ini의 Name="Target" 줄. #define ECC_Target ECC_GameTraceChannel1로 이름 붙이기. DefaultEngine.ini는 커밋 필수

델리게이트 매개변수: ~Params 매크로 읽기

함수 이름(OnComponentEndOverlap)에서 F12 → 선언 매크로로.

DECLARE_DYNAMIC_MULTICAST_SPARSE_DELEGATE_FourParams(
    FComponentEndOverlapSignature,   // 이름표: 델리게이트 자료형
    UPrimitiveComponent,             // 이름표: 가진 클래스
    OnComponentEndOverlap,           // 이름표: 변수 이름
    UPrimitiveComponent*, OverlappedComponent,   // 쌍 1
    AActor*,              OtherActor,            // 쌍 2
    UPrimitiveComponent*, OtherComp,             // 쌍 3
    int32,                OtherBodyIndex         // 쌍 4
);

void OnSphereTriggerExit(UPrimitiveComponent* OverlappedComp, AActor* Other, UPrimitiveComponent* OtherComp, int32 OtherBodyIndex);
  • FourParams = (자료형, 이름) 쌍 4개. Begin은 SixParams라 bool bFromSweep, const FHitResult& SweepResult가 더 있음
  • 자료형과 순서는 정확히, 이름은 자유. 함수에는 UFUNCTION()
  • SPARSE가 붙은 건 이름표 3개, 일반 DECLARE_DYNAMIC_MULTICAST_DELEGATE_~Params는 이름표 1개

Epic 공식 · 모든 델리게이트(OnComponentHit, OnClicked …)에 같은 방법

부모 포인터 → 자식 변수: No viable operator=

증상
긴 에러: No viable operator= matches arguments of type TObjectPtr<USphereComponent> and UShapeComponent*
원인
자동완성이 CreateDefaultSubobject<UShapeComponent>를 골랐다. CreateDefaultSubobject<T>는 T*를 돌려주고, 부모(Shape)를 자식(Sphere) 변수에 그냥 못 넣는다
읽는 법
첫 줄만: "왼쪽(변수)에 오른쪽(값)을 넣을 방법이 없다" → 양쪽 자료형 비교. Candidates considered 이하는 처음엔 건너뛰기
UPrimitiveComponent
  └─ UShapeComponent        ← 부모: 구일 수도, 박스일 수도
       ├─ USphereComponent  ← 자식
       ├─ UBoxComponent
       └─ UCapsuleComponent

유니티에서 Collider를 캐스트 없이 SphereCollider 변수에 넣으려는 것과 같은 에러

override는 뒤에 (C# 습관)

override void OnConstruction(const FTransform& Transform);           // C# 모양 → Cannot resolve symbol
virtual void OnConstruction(const FTransform& Transform) override;   // C++
  • 같은 헤더의 virtual void BeginPlay() override;가 정답 모양. 헷갈리면 엔진이 만들어 준 코드를 따라 하기
  • .cpp 정의에는 virtual/override를 안 붙이고, 본문 첫 줄에 Super::OnConstruction(Transform);

UE_LOG: TEXT()는 글자만, FString엔 *

UE_LOG(LogTemp, Warning, TEXT("Enter(%s)", Other->GetName()));
UE_LOG(LogTemp, Warning, TEXT("Enter(%s)"), *Other->GetName());
  • TEXT()는 따옴표 글자 하나만 감싸는 매크로. 값은 UE_LOG의 다음 인자
  • %s는 TCHAR*를 받는다. FString 앞의 * = 안의 글자 배열 꺼내기 (곱하기 아님)
  • 화면에 띄우기: if (GEngine) { GEngine->AddOnScreenDebugMessage(키, 초, 색, 문자열); } + #include "Engine/Engine.h". 키 -1 = 쌓임, 양수 = 같은 줄 덮어쓰기(매 프레임 값)
  • 쓰는 헤더는 직접 include (IWYU). 우연히 되는 건 나중에 갑자기 깨진다

Rider의 MSBuild 선택

증상
MSB4019 … JetBrains Rider 2026.2 … \tools\MSBuild\Microsoft\VC\v180\Microsoft.Cpp.Default.props을 찾을 수 없음
원인
Rider가 VS 2022 대신 자기 번들 MSBuild로 빌드 → v180을 찾음. VS 2022에는 v170까지, UE 5.4는 VS 2022(v170)
해결
Rider Settings → Build, Execution, Deployment → Toolset and Build → MSBuild version = VS 2022의 MSBuild\Current\Bin\MSBuild.exe

코드 에러가 아니라 도구 에러. Intermediate 지우기·VS 재설치부터 하지 않기

작은 것들

  • Pawn vs Actor: Pawn = Controller(Player 또는 AI)가 조종할 수 있는 것. 조종할 필요 없는 터렛·타겟은 Actor. 블루프린트 부모는 편집기 오른쪽 위 Parent class:
  • FRotator 순서: (Pitch, Yaw, Roll). 수평 회전은 두 번째 칸. DeltaTime 곱하기 잊지 않기
  • Yaw / Pitch / Roll: Z(위) / Y(오른쪽) / X(앞)이 경첩
  • Yaw 표시: 180 다음에 -180으로 튄다. 버그 아님
  • 지역 변수도 PascalCase: result ✗ → Result (Epic 코딩 표준)
  • bool은 b 접두사: bHasLostLock
  • UPROPERTY엔 초기값: float RotateSpeedDeg = 90.f;
  • 남의 액터 기억하기: TSet<TWeakObjectPtr<AActor>> — 사라지면 자동 무효, 꺼낼 때 IsValid()
  • C++ 클래스 생성: 이름에 A를 빼고 입력 (Turret → ATurret). 이름은 나중에 바꾸기 번거롭다
  • 파일이 없다는 include 에러: 철자(Shpere) → 폴더 → 모듈 순서로
