회전 Pitch · Yaw · Roll: 이름은 같고, 축 글자와 순서가 다르다

미사일을 수직으로 쏘려고 FRotator(90, 0, 0)을 쓰다가 "언리얼은 Yaw Pitch Roll이 아니라 Pitch Yaw Roll이네?"에서 시작한 노트. 미사일 모형을 세 가지 동작으로 직접 돌려 보고, 언리얼과 유니티에서 같은 회전이 어떻게 적히는지 비교합니다.

Pitch(끄덕)·Yaw(도리도리)·Roll(갸우뚱)은 물체 자신을 기준으로 한 동작 이름이라 두 엔진에서 뜻이 같다. 다른 건 ① 그 동작에 붙는 축 글자, ② 에디터와 코드의 칸 순서, ③ Pitch의 부호.

실험 · 미사일 돌려 보기

파란 화살표가 미사일의 앞, 주황 점이 달린 날개가 오른쪽, 초록이 위입니다. 미사일을 왼쪽 옆에서 비스듬히 보는 그림이에요(오른쪽은 화면 안쪽으로). 엔진을 바꾸면 축 이름과 아래 숫자가 바뀌지만 미사일은 똑같이 돕니다.

이름은 물체 기준 동작

이름동작도는 축 (물체 기준)언리얼 축유니티 축
Yaw도리도리 — 좌우로 고개 돌리기위 축ZY
Pitch끄덕끄덕 — 고개 들고 숙이기옆 축YX
Roll갸우뚱 — 고개 기울이기앞 축XZ

엔진마다 위·앞·옆에 붙인 글자가 다를 뿐입니다. 언리얼은 Z가 위, X가 앞, 유니티는 Y가 위, Z가 앞이에요.

칸 순서: 언리얼은 에디터와 코드가 어긋난다

첫째 칸둘째 칸셋째 칸
언리얼 코드 FRotator(…)PitchYawRoll
언리얼 Details X / Y / ZRollPitchYaw
유니티 코드 Quaternion.Euler(x, y, z)PitchYawRoll
유니티 인스펙터 X / Y / ZPitchYawRoll
  • 유니티는 Y가 위라서 축 순서(x, y, z)와 동작 순서(Pitch, Yaw, Roll)가 우연히 맞습니다. 그래서 헷갈릴 일이 없었어요.
  • 언리얼은 Details는 축 순서(X=Roll, Y=Pitch, Z=Yaw), 코드는 Pitch-Yaw-Roll이라 둘이 어긋납니다(Epic 공식).
// 미사일 수직 발사 — 레벨에서 Details의 Y 칸에 90을 넣었던 것
Details:  X(Roll)=0   Y(Pitch)=90   Z(Yaw)=0
코드:     FRotator(90.f, 0.f, 0.f)     // (Pitch, Yaw, Roll)

부호: Pitch +90은 언리얼에선 위, 유니티에선 아래

"아래를 보게 하려면 +90"은 유니티 감각입니다. 언리얼에서 그렇게 쓰면 미사일이 위로 가요. 이번 수직 발사는 우연히 원하는 방향이었지만, 나중에 아래로 쏠 때 반대로 쓰기 쉽습니다. 확인은 눈이 아니라 값으로: GetActorForwardVector()의 Z가 +1이면 위, −1이면 아래.

같이 기억할 것: 도와 라디안

함수각도 단위이번에 쓴 곳
FRotator(Pitch, Yaw, Roll)도수직 발사 FRotator(90.f, 0.f, 0.f)
AddActorLocalRotation(FRotator(…))도터렛 제자리 회전
Vector.RotateAngleAxis(각도, 축)도레이더 경계선
FQuat(축, 각도)라디안미사일 유도 회전

FRotator는 사람이 읽기 좋은 "세 동작의 각도(도)"이고, FQuat은 "축 하나 + 각도(라디안)"입니다. 미사일 유도처럼 외적으로 구한 임의의 축으로 돌릴 때는 Pitch·Yaw·Roll로 나누기 어려워서 FQuat을 썼어요.
