## 지금까지 잡은 감

- 문을 밀면 문이 도는 축(경첩)이 있음. **화살표 두 개(문, 미는 힘)를 넣으면 그 경첩 방향이 나오는 것**이 외적
- 그 축은 두 화살표 **모두와 직각**
- 반대쪽에서 밀면 경첩 화살표가 위↔아래로 뒤집힘 (문이 반대로 돎)
- 문과 같은 방향으로 밀면 문이 안 돎 → 외적 길이 0

## 내적과 비교

| | 내적 dot | 외적 cross |
|---|---|---|
| 나오는 것 | 숫자 하나 | 화살표 하나 |
| 알려주는 것 | 얼마나 같은 쪽인가 | 어느 축으로, 어느 쪽으로 도나 |
| 종이에서 | 공기를 얼마나 세게 받나 | 어느 쪽으로 뒤집히나 |

- 45°와 315°는 dot이 둘 다 0.71로 같음. cross는 +0.71과 -0.71로 갈림 → 내적이 못 하던 "왼쪽이냐 오른쪽이냐"

## 언리얼에서 외울 한 줄

```
cross(앞 X, 오른쪽 Y) = 위 Z
cross(오른쪽 Y, 앞 X) = 아래 -Z     // 순서를 바꾸면 반대
```

- 언리얼은 왼손 좌표계, Z가 위 (Epic 공식). Unity도 왼손이라 `Vector3.Cross(forward, right) = up`으로 같음
- 수학책·블렌더의 "오른손 법칙" 그림은 방향이 반대로 보임. 계산식은 같음

## 우리 코드에서 나온 곳

| 위치 | 코드 | 역할 |
|---|---|---|
| 3-1 법선 | `cross(Q.xyz, up)`, `cross(Q.xyz, t)` | 쿼터니언 회전 공식 안 (블랙박스로 둬도 됨) |
| 3-3 펄럭임 | `cross(N, v)` | **종이를 비트는 축.** 회전 편에서 다시 |
| 3-3 회전 누적 | `cross(OutAngVel, Q.xyz)` | 쿼터니언 누적 공식 안 (블랙박스) |

## 🚨 함정

- 순서가 중요: `cross(N, V)`와 `cross(V, N)`은 정반대 축. 내적은 순서를 바꿔도 같아서 이 습관이 생기기 쉬움
- 두 화살표가 한 줄이면 길이 0 → 축이 사라짐. 그대로 normalize하면 0으로 나누기
