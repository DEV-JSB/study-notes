# 외적은 벡터 하나: 방향은 축, 길이는 sin

> GameMathLab · 과정 1 · 내적·외적 복습 · 2026-10-31 — 직접 돌려 보는 그림은 [cross-product.html](cross-product.html)

**외적 → 어느 축으로 돌지. 내적 → 얼만큼 돌지. 외적 크기(sin)로 얼만큼을 구하면, 타겟이 뒤쪽일 때 덜 돈다.**

## 1. 외적의 결과는 언제나 벡터 하나

| UE C++ | Unity C# | 결과 자료형 | 예: 앞 (1,0,0)과 앞 30° 목표 |
|---|---|---|---|
| `FVector::DotProduct(A, B)` | `Vector3.Dot(a, b)` | 숫자 | 0.87 |
| `FVector::CrossProduct(A, B)` | `Vector3.Cross(a, b)` | **벡터** | (0, 0, 0.5) |
| `C.Size()` | `c.magnitude` | 숫자 (외적 벡터의 길이) | 0.5 |
| `C.GetSafeNormal()` | `c.normalized` | 벡터 (외적 벡터의 방향만) | (0, 0, 1) |

- 내적은 처음부터 숫자, 외적은 처음부터 벡터
- 외적 벡터 하나에 **방향 칸(회전축)** 과 **길이 칸(sin)** 이 같이 들어 있다
- 미사일 코드는 `GetSafeNormal()`로 방향 칸만 썼다

## 실험 1에서 버튼 순서대로 볼 것 (3D, 언리얼 축)

| 버튼 | 보이는 것 | 뜻 |
|---|---|---|
| ① X × Y | C = (0, 0, 1) | 앞 × 오른쪽 = 위. C는 A에도 B에도 수직 |
| ② 순서 바꾸기 | C = (0, 0, −1) | 길이 같고 방향만 정반대 |
| ③ 앞 30° | C = (0, 0, 0.5) | 길이 0.5 = sin 30° |
| ④ 뒤 150° | C = (0, 0, 0.5) | ③과 벡터 전체가 똑같다 |
| ⑤ 정반대 180° | C = (0, 0, 0) | 뒤를 보는 축은 무수히 많아서 하나로 못 정함 |

### "외적을 하면 값이 2개 나오나?" → 아니요, 하나

- `CrossProduct`를 한 번 부르면 결과는 벡터 하나
- ③과 ④는 타겟 위치가 다른 두 상황이 우연히 같은 결과를 낸 것
- 인자 순서를 바꾸면 방향이 정반대인 벡터 하나가 나온다. 미사일은 `CrossProduct(Forward, ToTarget)` 순서

## 2. C의 길이가 왜 sin인가 — 평행사변형 넓이

- A, B가 길이 1이면 C의 길이 = sin(사이 각도). 일반적으로는 A 길이 × B 길이 × sin
- C의 길이 = A와 B가 펼친 평행사변형의 넓이
- 넓이 = 밑변 × 높이 (초등 5학년) = 1 × B의 옆 조각 = sin (sin은 중3 삼각비)

| 사이 각도 | .Size() | 평행사변형 |
|---|---|---|
| 90° | 1.00 | 가장 넓음 |
| 30° | 0.50 | 납작함 |
| 150° | 0.50 | 30°와 같은 넓이 |
| 180° | 0.00 | 선 |

## 3. 미사일에게 숫자 하나만 알려 준다면

| 미사일이 받은 숫자 | 타겟이 있을 수 있는 곳 | 하나로 정해지나 |
|---|---|---|
| 외적 길이 = 0.5 | 앞쪽 30° 또는 뒤쪽 150° | ✕ 두 곳 |
| 내적 = +0.87 | 앞쪽 30° | ○ 한 곳 |
| 내적 = −0.87 | 뒤쪽 150° | ○ 한 곳 |

### 외적 벡터의 방향은 믿어도 된다

| 칸 | 코드 | 알려 주는 것 | 믿어도 되나 |
|---|---|---|---|
| 방향 | `.GetSafeNormal()` | 어느 쪽으로 돌지 | ○ (정확히 앞·뒤일 때만 비어 있음) |
| 길이 | `.Size()` | 옆으로 얼마나 (sin) | △ "얼만큼"으로는 못 씀 |

- 30°와 150° 타겟은 같은 쪽에 있어서 돌아야 할 쪽도 같다. 다른 건 양뿐이고, 그걸 내적이 채운다

## 실험 2: 외적 크기로 '얼만큼'을 구해서 한 번에 돌리면

| 실제 타겟 각도 | 외적 크기 | Asin으로 구한 각도 | 맞나 |
|---|---|---|---|
| 30° (앞쪽) | 0.5 | 30° | ○ |
| 60° (앞쪽) | 0.87 | 60° | ○ |
| 120° (뒤쪽) | 0.87 | 60° | ✕ 60° 덜 돎 |
| 150° (뒤쪽) | 0.5 | 30° | ✕ 120° 덜 돎 |

- `Asin`은 0°~90° 답만 준다 → 뒤쪽 타겟을 "앞쪽 거울 위치"로 착각
- `Acos`는 0°~180°를 다 구별한다 → 얼만큼은 내적으로
- `FMath::Asin`, `FMath::Acos` (Unity `Mathf.Asin`, `Mathf.Acos`)는 라디안을 돌려준다
- 참고: 매 프레임 다시 계산하는 미사일은 Asin이어도 결국 따라가긴 한다. 그래도 식으로는 틀린 값

## 4. 헷갈렸던 이유 — 두 이야기가 섞였다

| 이야기 | 무슨 문제인가 | 내 미사일 코드에 해당하나 |
|---|---|---|
| 30° vs 150° | 외적 크기로 '얼만큼'을 구할 때만 생김 | 해당 없음 |
| 180° | 외적 축이 (0, 0, 0)이 돼서 사라짐 | 타겟이 정확히 뒤일 때만 |

## 5. 내 미사일 코드 (Missile.cpp)

```cpp
const FVector Rotate = FVector::CrossProduct(ForwardVector,ToTarget).GetSafeNormal();

const float DotResult = FMath::Clamp(FVector::DotProduct(ForwardVector,ToTarget),-1.f,1.f);
const float Radian = FMath::Acos(DotResult);
const float Angle = FMath::RadiansToDegrees(Radian);

const float RotateSpeed = FMath::Min(Angle , TargetChaseRotateSpeedDeg * DeltaTime);
AddActorWorldRotation(FQuat(Rotate, FMath::DegreesToRadians(RotateSpeed)));
```

| 줄 | 하는 일 | 쓰는 것 |
|---|---|---|
| `Rotate` | 회전축 = 외적 방향 칸 | 외적 |
| `DotResult` → `Angle` | 얼만큼 = Acos(내적) | 내적 |
| `RotateSpeed` | 남은 각도보다 많이 돌지 않기 (없으면 목표 근처에서 떨림) | Min |
| `FQuat(Rotate, …)` | 그 축으로 그 각도만큼 | 둘을 합침 |

- 외적은 문의 경첩: 문짝(앞 방향)이 옆으로 넘어가려면 수직으로 선 경첩이 필요. 외적이 경첩 방향, 내적이 몇 도 열지

## 6. 내가 던진 질문들 (2026-10-31)

> "결국 외적을 통해서 얻은 벡터는 어느쪽으로 기울어야하나를 정하는거고, 얼만큼은 결국 내적을 통해서 알아내야하는거다."

- **맞음.** "기울어야 하나"보다 "어느 축을 중심으로 도나"가 정확

> "내적의 값을 소수로 말했고 외적의 값을 Vector로 말했단말이야… 근데 또 설명 자료에서는 외적 길이 소수야. 벡터 어디감?"

- **좋은 의심.** 외적은 언제나 벡터, "외적 길이"는 거기서 꺼낸 숫자. 평면 그림에서는 외적 벡터가 화면에 수직이라 안 보였다

> "외적을 할 때는 2개의 값이 나온다는 건가? 뭘 인자로 먼저 넣느냐에 따라인 건가?"

- **아니요, 하나.** 30°/150°는 다른 두 상황이 같은 결과. 순서를 바꾸면 정반대 벡터 하나

> "외적으로는 벡터도 나온다고 하지 않았어? 그 벡터가 곧 방향 아님?"

- **맞음.** 방향 칸은 믿어도 된다

> "C의 크기가 sin 값이라는 건가?"

- **맞음** (A, B가 길이 1일 때). 평행사변형 넓이

> "그니까 외적으로 회전축도 구하고 얼만큼 회전을 시키려고 했을 때가 문제다?"

- **정확히 맞음.** 설명 듣기 전에 핵심을 먼저 집어냄

> "걍 무시하고 외적의 값으로 진행시키면 타겟 위치가 30도에 있다는 가정의 타겟으로 가게 되나?"

- **맞음.** Asin(0.5) = 30°, 올바른 쪽으로 30°만 돌고 120° 어긋남

## 덤: 회전을 담는 그릇 — 지금 내가 아는 만큼 (2026-11-01)

복습 끝에 "축 하나로 실제로 어떻게 돌리지? → 쿼터니언"으로 이어진 이야기. 다음에 꼭 할 주제라는 뜻이 아니라, 지금 이해한 정도를 적어 두는 칸.

> "쿼터니언은 결국 행렬을 쓰기 위한 거고… 축 소멸? 축 하나가 소멸이 될 수 있어서 그냥 행렬로 한 번에 회전시킨다? 행렬 특성상 연산에도 더 유리하고, 렌더링 파이프라인에서도 행렬을 쓰니까 그래픽카드가 하기 딱 좋은 방식."

- **반쯤 맞음.** 두 이야기가 한 덩어리로 섞여 있었음
  - 맞음: "축 소멸" = **짐벌 락(Gimbal lock)**. Pitch·Yaw·Roll을 차례로 돌릴 때, 예를 들어 Pitch 90°에서 축 두 개가 겹쳐 돌릴 방향 하나가 사라짐
  - 맞음: GPU는 4×4 행렬 하나로 이동·회전·크기를 한꺼번에 처리
  - 틀림: 쿼터니언은 행렬이 아니라 다른 그릇. 짐벌 락은 오일러 각만의 문제라 행렬로도 쿼터니언으로도 피할 수 있음
  - 빠짐: 게임 로직에서는 쿼터니언으로 들고 다니고(저장·합치기·부드러운 보간), 그리기 직전에 행렬로 바꿔 GPU에 넘김. 경쟁이 아니라 이어 달리기

"각"이 아니라 **"회전(방향)"** 을 표기하는 수단. 각은 숫자 하나(30°), 3D 회전은 "어느 축으로 얼마나"라 숫자 하나로 못 담는다.

| 표기 방법 | 담는 방식 | UE | 내가 만난 곳 |
|---|---|---|---|
| 오일러 각 (Euler angles) | Pitch·Yaw·Roll 각도 3개 | `FRotator` | Details 패널 Rotation 칸, [회전 노트](rotation-pyr.md). 짐벌 락 있음 |
| 축-각 (Axis-Angle) | 축 벡터 1개 + 각도 1개 | 축과 각도를 따로 들고 있음 | 오늘 복습: 외적 = 축, 내적 = 각도 |
| 쿼터니언 (Quaternion) | 숫자 4개 (x, y, z, w) | `FQuat` | 미사일 `FQuat(Rotate, 라디안)`. `FTransform`도 회전을 이걸로 저장 |
| 회전 행렬 (Rotation matrix) | 3×3 숫자 9개 (이동·크기까지 4×4) | `FMatrix` | 아직 직접 쓴 적 없음 (렌더링 쪽) |

- 내 미사일은 외적·내적으로 축-각을 만들고, `FQuat(축, 각도)`로 쿼터니언으로 바꿔서 돌린다 → 짐벌 락 걱정이 없었다
- 각도 단위 함정: UE `FQuat(Axis, Angle)`는 라디안, Unity `Quaternion.AngleAxis(angle, axis)`는 도
- 아직 모르는 것: 쿼터니언 숫자 4개가 각각 무엇인지, 왜 각도의 절반이 들어가는지
