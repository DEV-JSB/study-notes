타겟 쪽으로 돌기: 외적은 어느 쪽, 내적은 얼마나

유도 미사일이 매 프레임 "어느 쪽으로, 몇 도" 돌지 정하는 방법. 위에서 내려다본 미사일을 직접 날려 보고, 오늘 실제로 겪은 버그 세 개를 스위치로 켜서 어떻게 망가지는지 봅니다.

회전 하나 = 축 + 각도. 축(어느 쪽으로)은 외적, 각도(얼마나)는 내적을 각도로 되돌려서 구하고, 이번 프레임에는 남은 각도와 최대 회전 중 작은 쪽만큼만 돈다.

해 볼 것: 최대 회전을 30으로 내리면 크게 돌다 놓치고, 720으로 올리면 거의 꺾여서 따라갑니다. 스위치를 하나씩 켜 보고 남은 각도가 어떻게 되는지 보세요.

회전 하나 = 축 + 각도

유니티의 Quaternion.AngleAxis(각도, 축)을 떠올리면 됩니다. 회전을 만들려면 두 가지가 필요해요.

필요한 것무엇으로 구하나언리얼유니티
어느 쪽으로 (축)외적FVector::CrossProduct(A, B)Vector3.Cross(a, b)
얼마나 (각도)내적 → 각도로 되돌리기FMath::Acos(Clamp(Dot, -1, 1))Vector3.Angle(a, b)
둘을 합쳐 돌리기FQuat(축, 라디안)Quaternion.AngleAxis(도, 축)

내적만 있으면 "30° 차이 난다"까지는 알지만, 왼쪽으로 30°인지 오른쪽인지 위로인지는 모릅니다(레이더 원뿔에서 왼쪽 50°와 오른쪽 50°가 같은 값이었던 것). 그 "어느 쪽"을 외적이 정합니다.

작업자가 정리한 문장: "타겟 쪽을 보려면, 내가 보는 방향과 타겟으로의 방향을 외적해서 어느 쪽으로 돌지 알아내고, 내적으로 얼마나 돌지 구한다."

외적 = 고개를 돌릴 축

내 고개(앞 방향)를 목표 쪽으로 돌린다고 생각해 보세요. 목표가 오른쪽이면 고개를 옆으로 돌리고(정수리를 꿰뚫는 위아래 축), 목표가 위면 고개를 듭니다(양쪽 귀를 잇는 좌우 축). 외적은 두 방향을 넣으면 그 축을 계산해 줍니다.

점선은 도는 쪽. 숫자는 실제 CrossProduct 결과입니다. 외적으로 나온 축은 두 방향 모두에 수직이에요.

축은 길이 1로 — 방향만 쓰려고

외적 결과는 방향은 맞지만 길이가 제각각입니다. 두 방향이 많이 벌어질수록 깁니다.

앞 방향목표 방향사이 각도외적길이
(1, 0, 0)(0, 1, 0)90°(0, 0, 1)1
(1, 0, 0)(0.87, 0.5, 0)30°(0, 0, 0.5)0.5
(1, 0, 0)(0.9998, 0.017, 0)1°(0, 0, 0.017)0.017

FQuat(축, 각도)는 축이 길이 1이라고 믿고 계산합니다(Epic 공식). 얼마나는 각도가 따로 맡으니, 축에는 .GetSafeNormal()을 붙여 방향만 남깁니다. 유니티 Quaternion.AngleAxis는 안에서 정규화해 줘서 신경 쓸 일이 없었어요.

내적 → 각도: Acos 앞에는 Clamp

길이 1끼리 내적하면 cos(사이 각도)가 나옵니다(내적은 그림자 길이). Acos는 그걸 거꾸로 각도로 되돌리는 함수예요. 결과는 라디안입니다.

cos 값은 −1 ~ 1에만 있습니다. 그런데 컴퓨터 소수 오차로 1.0000001이 나올 수 있고, 하필 유도가 잘 돼서 타겟을 거의 정면으로 볼 때 그렇습니다. NaN이 회전에 들어가면 위치까지 NaN이 되어 미사일이 사라져요. FMath::Acos는 범위를 검사하지 않으니 부르기 전에 잘라 둡니다. 유니티 Vector3.Angle이 안에서 하는 일도 정확히 이것입니다.

const float DotResult = FMath::Clamp(FVector::DotProduct(ForwardVector, ToTarget), -1.f, 1.f);
const float Radian = FMath::Acos(DotResult);           // 라디안
const float Angle = FMath::RadiansToDegrees(Radian);   // 도

이번 프레임 각도: 남은 것과 최대 중 작은 쪽

60fps, 최대 회전 180°/s라면 한 프레임에 돌 수 있는 최대는 180 × 0.016 ≈ 2.9°입니다.

Min이 없으면 남은 각도보다 더 돌아서 반대쪽으로 지나치고, 다음 프레임에 또 지나치며 좌우로 떨립니다. 그래서 TargetChaseRotateSpeedDeg의 뜻은 "초당 최대 회전"이 됩니다. 이 숫자 하나로 미사일 성격이 정해져요(작으면 피할 수 있고, 크면 못 피함).

dt는 "초당 값"에만 곱한다

값뜻단위dt
TargetChaseRotateSpeedDeg1초에 최대 몇 도도/초곱함 → 도
Angle지금 남은 각도도 (이미 양)안 곱함
Min(...) 결과이번 프레임에 돌 각도도안 곱함 (또 곱하면 60배 느림)

단위로 확인: Angle × (최대 × dt) = 도 × 도 = 도². 각도가 아니라서 틀린 식이라는 게 바로 보입니다. 이동에서 "목적지까지 남은 거리에는 dt를 안 곱한다"와 같은 이유예요.

함정 모음

  • 빼기 순서: 화살표는 도착 − 출발. 나 − 타겟이면 미사일이 도망갑니다 (위 실험 스위치 3).
  • 외적 순서: 순서를 바꾸면 축이 반대. 미사일이 타겟에서 고개를 돌립니다 (스위치 1). 남은 각도가 줄지 않고 180° 쪽으로 커지는 걸 확인하세요.
  • Acos NaN: 내적을 −1~1로 Clamp한 뒤 넣기.
  • 축 길이: FQuat에 넣기 전 .GetSafeNormal().
  • 라디안: Acos는 라디안을 돌려주고, FQuat은 라디안을 받습니다. 바꿔야 하는 건 도로 적은 회전 속도 쪽이에요. 이름에 Deg/Rad를 붙이면 덜 헷갈립니다.
  • 정반대 타겟: 타겟이 정확히 바로 뒤면 두 방향이 일직선이라 외적이 (0,0,0)입니다. 축이 없어서 영영 안 돌 수 있어요 ("타겟을 바로 뒤에" 버튼). 실제 게임은 이때 아무 축이나 하나 골라 돌리곤 합니다.
  • dt: 초당 값에만 곱합니다. 남은 각도나 Min 결과에는 곱하지 않습니다.
