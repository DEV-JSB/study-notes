# 꼬챙이로 보는 torque

> ProjectF · PaperAero ③ 복습 · 2026-10-29 — 직접 돌려 보는 3D 그림은 [torque-skewer.html](torque-skewer.html)

**N과 V가 놓인 평면에 수직으로 꼬챙이(외적)를 꽂는다. 종이는 그 꼬챙이를 중심으로 평면 안에서 돈다. 꼬챙이를 앞으로 꽂을지 뒤로 꽂을지는 내적의 부호가 정한다. → N은 V와 −V 중 더 가까운 쪽으로 돈다.**

## 이 노트가 나온 코드

ProjectF 종이 모듈 `PaperAero`의 ③ 회전 속도 덩어리 ([PaperAero 한 장 지도](../projectf/paper-aero-map.html) ③)

```hlsl
float3 v = Vel * 0.01f;                                    // cm/s → m/s
float3 torque = dot(N, v) * cross(N, v) * FlipStrength;    // ← 이 노트의 주인공
float keepSpin = max(0.0f, 1.0f - SpinDrag * DeltaTime);
float air = 1.0f - Landed;
float3 flatN = float3(0.0f, 0.0f, step(0.0f, N.z) * 2.0f - 1.0f);
float3 settle = cross(N, flatN) * SettleSpeed;
OutAngVel = (AngVel + torque * DeltaTime) * keepSpin * air + settle * Landed;
```

| 줄 | 하는 일 |
|---|---|
| `torque` | 떨어지며 맞는 공기가 종이를 **어느 꼬챙이로 얼마나 세게** 비트나 (외적 = 꼬챙이, 내적 = 앞뒤와 세기) |
| `AngVel + torque * DeltaTime` | 그 비틀림을 회전 속도에 조금씩 **더한다** (속도에 중력을 더하는 것과 같은 모양) |
| `* keepSpin` | 회전 브레이크 |
| `* air + settle * Landed` | 공중이면 torque 쪽, 바닥이면 눕히기 쪽 (0/1 곱해서 고르기) |
| 그다음 ④ | `OutAngVel`만큼 이번 프레임 종이를 실제로 돌림 |

## torque가 있으면, 없으면

같은 높이(3m), 기울기 15°에서 떨어뜨림. 공기저항·중력은 똑같고 torque 줄만 다름 (NormalDrag 8, PlaneDrag 0.5, FlipStrength 30, SpinDrag 3, 중력 980). 그림으로 겹쳐 보는 건 [torque-skewer.html](torque-skewer.html) 실험 1

| | torque 줄 | 떨어지는 시간 | 옆으로 간 거리 | 모습 |
|---|---|---|---|---|
| 있음 | `dot(N, v) * cross(N, v) * FlipStrength` | 약 2.0초 | 좌우로 왔다 갔다 (−5 ~ +18cm) | **펄럭임** |
| 없음 | `0` (FlipStrength 0과 같음) | 약 1.9초 | 한쪽으로 약 290cm | 기운 채 쭉 미끄러짐 |
| 외적만 | `cross(N, v) * FlipStrength` (내적 뺌) | 약 1.4초 | 약 40cm | 통째로 뒤집히며 굴러떨어짐 |

- **있음**: 기울면 판을 따라 미끄러짐 → 넓은 면이 공기를 정면으로 받으려고 **더 가까운 쪽**으로 돎 → 지나쳐서 반대로 기움 → 반복
- **없음**: 돌게 하는 게 없어서 기울기가 그대로. ② 공기저항만 남아 판을 따라 활강
- **외적만**: 내적이 없으면 언제나 N → v 쪽. 하늘을 보던 N이 떨어지는 방향(아래)까지 **먼 길로 반 바퀴** 돌아감
- 시작 기울기 0°면 셋 다 똑같이 곧게 떨어짐 — N과 v가 일직선이라 외적 0 ("평평한 종이는 안 펄럭임")

## 50°와 130°: 외적만으로는 똑같다

| N과 v 사이 | 외적 길이 (sin) | 내적 (cos) | 꼬챙이 | 도는 쪽 |
|---|---|---|---|---|
| 50° | 0.77 | +0.64 | 그대로 | v 쪽으로 50° |
| 130° | 0.77 | −0.64 | **뒤집힘** | −v 쪽으로 50° (v까지 130°를 돌지 않음) |
| 90° | 1 | 0 | 사라짐 | 안 돎 (v와 −v가 똑같이 멂 — 불안정한 자리) |
| 0° / 180° | 0 | ±1 | 없음 | 안 돎 — 넓은 면이 이미 정면으로 맞음 (멈춤 자리) |

꼬챙이를 뒤집는 건 화살표에 음수를 곱하는 것 (늘이고 줄이기).

```
(0, 3, 0) ×  2 = (0,  6, 0)   같은 방향, 더 셈
(0, 3, 0) × −1 = (0, −3, 0)   반대 방향 → 반대로 돎
(0, 3, 0) × −4 = (0,−12, 0)   반대 방향 + 4배 셈
```

- 미사일에서 외적 순서를 바꿨더니 "딱 반대로" 도망간 것(`cross(B, A) = −cross(A, B)`)과 같은 일을, 순서 대신 음수 곱하기로 한 것

## 손 계산

```
N = (0, 0, 1)    종이가 하늘을 보고 누움
V = (3, 0, −4)   +X 쪽으로 미끄러지며 떨어짐

cross(N, V) = (0, 3, 0)   → Y 꼬챙이: 종이 가운데를 양옆으로 꿰뚫음
dot(N, V)   = −4          → N은 −V 쪽에 더 가까움
torque      = (0, −12, 0) × FlipStrength → 꼬챙이가 뒤집혀 −V 쪽으로 끄덕임
```

- Y 꼬챙이로 도는 건 고개를 끄덕이는 Pitch와 같은 모양
- 외적 = "Yaw로 돌아 / Pitch로 돌아 / 섞은 비스듬한 막대로 돌아"를 계산해 주는 것

## 각도는 아무도 구하지 않는다

| | 미사일 | 종이 |
|---|---|---|
| 꼬챙이 | 외적, 길이는 버림 (`GetSafeNormal`) | 외적 그대로 |
| 내적 | `Acos`로 **각도까지** 구함 | 각도는 안 구하고 **숫자 그대로 곱함** (부호 = 앞뒤, 크기 = 세기) |
| 결과 | "이만큼 돌아" | "이 꼬챙이로 이만큼 빠르게 돌아" (각속도) |
| 멈춤 | 남은 각도가 0 | N이 V나 −V와 나란해지면 외적이 0 → 저절로 멈춤 |

## 같은 꼬챙이가 나오는 곳

| 어디서 | 꼬챙이 | 앞뒤를 정하는 것 |
|---|---|---|
| 터렛 (GameMathLab) | `cross(앞, 타겟 방향)` → 거의 Z 막대 = Yaw | 순서 |
| 유도 미사일 | 솟았다 꺾일 때 비스듬한 막대 | 순서 |
| 종이 펄럭임 (③ torque) | `cross(N, v)` | **내적 부호** — 더 가까운 쪽 |
| 종이 눕기 (③ settle) | `cross(N, flatN)` | `flatN`을 위·아래 중 가까운 쪽으로 미리 골라 둠 (`step(0, N.z)`) |
| 4단계 예고: 모서리를 차면 돈다 | `cross(가운데→닿은 곳, 미는 힘)` | 어디를 미느냐 |

## 내가 정리한 문장

> "N과 V를 외적함으로써, N과 V로 이루어져 있는 2차원 평면이 있다고 하면 그 평면에 수직선을 꽂아야 하는데, 그걸 앞으로 꽂을지 뒤로 꽂을지는 내적으로 정하는 건가!?"

- **맞음.** 덧붙이면 외적도 혼자서 꽂는 방향을 하나 정한다(N → V 쪽). 내적은 −V가 더 가까우면 그걸 반대로 다시 꽂는다

> "torque는 바람으로 인해서 영향을 받는 종이를 만들기 위해 존재하는 거네. 외적으로 인해서 돌아야 할 각도는 아는데, 그 각도를 가까운 쪽으로 돌리기 위해서 내적의 값을 곱한다?"

- **거의 맞음.** 외적이 주는 건 각도가 아니라 **축(꼬챙이)**. 바람은 바깥 바람이 아니라 **종이가 떨어지며 스스로 맞는 공기** (v = 종이 자신의 속도)
