# 내적은 숫자, 외적은 화살표: cos와 sin으로 보기

> GameMathLab · 과정 1 · 내적·외적 다지기 · 2026-10-28 — 직접 돌려 보는 그림은 [dot-cross.html](dot-cross.html)

**길이 1인 두 화살표에서 내적 = cos(사이 각도), 숫자 하나. 외적 = 화살표: 방향은 돌릴 축, 길이는 sin(사이 각도). 그런데 sin은 30°와 150°가 같아서, 각도는 내적으로 구한다.**

## 그림자 조각과 옆 조각

- 길이 1인 화살표를 앞 방향 기준으로 나누면
  - **그림자 조각** (앞 방향 위) = cos = 내적
  - **옆 조각** (그림자에서 비켜 난 길이) = sin = 외적 길이
- 둘은 직각 → cos² + sin² = 1 (빗변 1인 직각삼각형의 피타고라스, 중2)

| 사이 각도 | 내적 (cos) | 외적 길이 (sin) |
|---|---|---|
| 0° | 1 | 0 |
| 30° | 0.866 | 0.5 |
| 90° | 0 | 1 |
| 150° | −0.866 | 0.5 |
| 180° | −1 | 0 |

## 왜 외적 길이로는 30°와 150°를 구별 못 하나

- 30°와 150° 화살표는 **옆 방향 축을 기준으로 거울 대칭**
  - 옆 조각(sin): 거울에 비춰도 높이 그대로 → 둘 다 0.5
  - 그림자 조각(cos): 좌우가 뒤집힘 → 0.866 / −0.866
- 미사일한테는 "조금만 꺾으면 되나, 거의 유턴해야 하나"의 차이

| 짝 | 내적 (cos) | 외적 길이 (sin) |
|---|---|---|
| 30° / 150° | 0.866 / −0.866 | 0.5 / 0.5 |
| 60° / 120° | 0.5 / −0.5 | 0.866 / 0.866 |
| 0° / 180° | 1 / −1 | 0 / 0 |

### 같은 값이 몇 번 나오나 (0°~180°)

- sin: 90°에서 꺾여 내려오는 산 모양 → 같은 값을 **두 번** 지남 (예: 0.5 → 30°, 150°)
- cos: 1에서 −1로 계속 내려가기만 함 → 어떤 값이든 **한 번** (예: 0.5 → 60°)
- 그래서 `Acos(내적)`은 각도를 하나로 정해 줌

## 미사일 코드의 역할 분담

| 정보 | 어디서 | 코드 |
|---|---|---|
| 얼마나 (각도) | 내적 | `FMath::Acos(FMath::Clamp(DotResult, -1.f, 1.f))` |
| 어느 쪽 (축) | 외적의 방향 | `FVector::CrossProduct(ForwardVector, ToTarget)` |
| 외적 길이 | 버림 | `.GetSafeNormal()` |

- 참고: 둘을 같이 쓰면 더 정확 → `FMath::Atan2(Cross.Size(), Dot)` (cos 부호로 30°/150° 구별, Clamp 불필요)

## sin은 이미 짜 본 적 있다: 종이의 vt

```hlsl
float3 vn = dot(Vel, N) * N;   // 그림자 조각 → cos 쪽
float3 vt = Vel - vn;          // 떼어낸 나머지 → sin 쪽
```

## 왜 내적은 숫자고 외적은 화살표인가

| | 질문 | 대답 |
|---|---|---|
| 내적 | 기준 방향으로 얼마나? | 기준은 하나 → 숫자 |
| 외적 | 옆으로 얼마나, 어느 옆? | 3D에서 "옆"은 무수히 많음 → 화살표 |

- 2D에서는 외적도 숫자 하나: `A.X × B.Y − A.Y × B.X` (+ 한쪽, − 반대쪽, 0 일직선)

## 내적도 "어디"를 말한다 — 단, 앞이냐 뒤냐 두 갈래만

"내적 = 얼마나, 외적 = 어느 쪽"은 반만 맞는 문장. 내적의 **부호**는 "같은 편인가, 반대 편인가"를 알려 준다.

| | 알려 주는 것 | 고를 수 있는 "어디" |
|---|---|---|
| 내적 | 부호 = **앞/뒤** (같은 편 / 반대 편) · 크기 = 얼마나 | **두 갈래** 중 하나 |
| 외적 | 어느 축으로 돌아야 B 쪽인가 | 빙 둘러 **무수히 많은 옆** 중 하나 |

| 어디서 | 내적으로 물은 것 |
|---|---|
| 터렛 레이더 원뿔 | 타겟이 **앞에** 있나 → 내적 > cos(반각) |
| 미사일 | 얼마나 돌아야 하나 → `Acos(내적)` |
| 종이 torque | N이 v 편인가 −v 편인가 → **부호로 축을 뒤집음** + 크기로 세기 |

### 종이 torque: 50°와 130°

```hlsl
float3 torque = dot(N, v) * cross(N, v) * FlipStrength;
```

| N과 v 사이 | 외적 길이 (sin) | 내적 (cos) | 실제로 도는 쪽 |
|---|---|---|---|
| 50° | 0.77 | +0.64 | v 쪽으로 50° |
| 130° | 0.77 | −0.64 | 축이 뒤집혀 **−v 쪽으로 50°** (v까지 130°를 돌지 않음) |

- 외적만 보면 둘이 똑같다 (30°/150°와 같은 문제)
- 내적 부호가 "v가 가깝다 / −v가 가깝다"를 고르고, 음수를 곱하면 축이 정반대 → **더 가까운 쪽으로** 돈다
- 화살표 × 음수 = 반대 방향 화살표 (늘이고 줄이기)

## 3D 외적 = 2D 외적 세 개 (몰라도 되는 칸)

```
축.Z = A.X × B.Y − A.Y × B.X    // 바닥(XY)
축.X = A.Y × B.Z − A.Z × B.Y    // 옆벽(YZ)
축.Y = A.Z × B.X − A.X × B.Z    // 앞벽(ZX)
```

| 앞 (1,0,0)일 때 목표 | 축 | 뜻 |
|---|---|---|
| 오른쪽 앞 (0.87, 0.5, 0) | (0, 0, 0.5) | 옆으로만 |
| 위쪽 앞 (0.87, 0, 0.5) | (0, −0.5, 0) | 고개만 듦 |
| 오른쪽 위 앞 (0.7, 0.5, 0.5) | (0, −0.5, 0.5) | 기울어진 축 |
| 정반대 (−1, 0, 0) | (0, 0, 0) | 축을 하나로 못 고름 |

## 내가 정리한 문장

> "2D 에서는 외적도 마찬가지로 그냥 숫자에 불과하지만, 3D 에서는 그런 단순 숫자를 가지고는 방향을 알 수가 없기 때문에 입체적으로 여러 평면들끼리의 외적을 합친 값을 구한다?"

- **맞음.** "합친" = 축의 X·Y·Z 칸에 하나씩 넣어 모은 것

> "내적은 어디로 회전해야 하는 게 아닌, 회전해야 하는 양밖에 필요하지 않으니까 굳이 3차원까지 갈 필요가 없다?"

- **반만 맞음.** 내적도 세 칸을 다 쓴다. 고친 문장: 내적도 3차원을 다 쓰지만, "얼마나"는 숫자 하나로 대답할 수 있어서 결과가 숫자다

> "앞으로 얼마나, 옆으로 얼마나 라고 하는 건 좀 헷갈리지 않나. 그렇게 따지면 외적으로도 cos와 같은, 얼마나 회전해야 하는 양을 알 수 있다는 건가"

- **좋은 의심.** 외적 길이로도 반쯤 알지만 30°/150°를 구별 못 함 → 각도는 내적

> "외적은 50도로 돌아도 50도 위치, 130도를 돌아도 50 위치. 이걸 내적을 이용해서 50도로 돌지 130도를 돌지… 그런 느낌인가" (2026-10-29)

- **맞음.** 30°/150°를 종이에서 스스로 다시 찾음. 종이에서는 한 걸음 더: 130°면 v까지 130°를 도는 대신, 내적 음수로 축을 뒤집어 −v 쪽으로 50°만 돈다

## 한 장 요약

| | 결과 | 길이 1끼리면 | 알려 주는 것 | 0° / 180° |
|---|---|---|---|---|
| 내적 | 숫자 | cos | 사이 각도, 부호 = 앞/뒤 두 갈래 | 1 / −1 |
| 외적 | 화살표 | 길이 = sin | 어느 쪽 (축) + 각도 힌트 | (0,0,0) / (0,0,0) |
