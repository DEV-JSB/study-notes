내적은 숫자, 외적은 화살표: cos와 sin으로 보기

유도 미사일을 만든 다음 날, "왜 정반대면 외적이 0이지?"에서 시작해 이어진 질문들을 그림으로 정리합니다. 핵심은 하나예요. 화살표 하나를 앞 방향 기준으로 그림자 조각과 옆 조각으로 나누면, 그게 cos와 sin입니다.

길이 1인 두 화살표에서 내적 = cos(사이 각도), 숫자 하나. 외적 = 화살표: 방향은 돌릴 축, 길이는 sin(사이 각도). 그런데 sin은 30°와 150°가 같아서, 각도는 내적으로 구한다.

실험 1 · 그림자 조각과 옆 조각

파란 화살표가 "내 앞 방향"(미사일 정면)이고, 검은 화살표가 목표 방향(길이 1)입니다. 슬라이더로 사이 각도를 바꿔 보세요. 보라 점선은 180° − θ에 있는 화살표예요.

왜 외적 길이로는 30°와 150°를 구별 못 하나

위 실험에서 30°를 누르면 검은 화살표와 보라 점선 화살표가 세로 점선(옆 방향)을 기준으로 거울처럼 마주 보고 있어요.

  • 옆 조각(주황)은 둘 다 같은 높이입니다. 거울에 비추면 높이는 그대로니까요. → sin 30° = sin 150° = 0.5
  • 그림자 조각(초록)은 하나는 앞쪽(+), 하나는 뒤쪽(−)으로 반대입니다. 거울에 비추면 좌우가 뒤집히니까요. → cos 30° = 0.866, cos 150° = −0.866
짝내적 (cos)외적 길이 (sin)뜻

60° / 120°0.5 / −0.50.866 / 0.866

외적 길이만 보고는 "목표가 내 앞쪽 비스듬히 있나, 뒤쪽 비스듬히 있나"를 모릅니다. 미사일한테는 "조금만 꺾으면 되나, 거의 유턴해야 하나"의 차이예요.

실험 2 · 같은 값이 몇 번 나오나

0°부터 180°까지 cos(초록)와 sin(주황)을 그린 그래프입니다. 가로선의 높이(값)를 바꾸면, 그 값이 되는 각도에 점이 찍힙니다.

sin은 90°에서 꺾여 내려오는 산 모양이라 같은 높이를 두 번 지나갑니다. cos는 1에서 −1로 계속 내려가기만 해서 어떤 값이든 딱 한 번. 그래서 Acos(내적)은 각도를 하나로 정해 주고, sin으로는 그게 안 돼요.

그래서 미사일 코드는 역할을 나눴다

참고: 내적(cos)과 외적 길이(sin)를 같이 쓰면 각도를 더 정확하게 구할 수 있어요. FMath::Atan2(Cross.Size(), Dot). cos 부호로 30°/150°를 가르고, Clamp도 필요 없습니다. 지금 코드(Acos + Clamp)로도 충분해요.

sin은 이미 짜 본 적 있다: 종이의 vt

종이 공기저항(PaperAero 지도 ②)에서 속도를 이렇게 쪼갰어요.

float3 vn = dot(Vel, N) * N;   // N 방향 그림자 조각  → cos 쪽 (초록)
float3 vt = Vel - vn;          // 그림자를 떼어낸 나머지 → sin 쪽 (주황)

vt가 실험 1의 주황 조각입니다. 화살표 길이가 1이면 vt의 길이가 정확히 sin이에요. 그리고 초록과 주황은 직각이라 cos² + sin² = 1은 빗변이 1인 직각삼각형의 피타고라스(중2)일 뿐입니다.

왜 내적은 숫자고 외적은 화살표인가

질문대답에 필요한 것
내적기준 방향으로 얼마나?기준은 하나뿐 → 숫자 (뒤쪽이면 −)
외적옆으로 얼마나, 어느 옆으로?3D에서 "옆"은 한 바퀴 빙 둘러 무수히 많음 → 방향을 담은 화살표

2D에서는 외적도 숫자 하나입니다. 평면에서 옆은 왼쪽·오른쪽 둘뿐이라 부호 있는 숫자로 충분해요.

2D 외적 = A.X × B.Y − A.Y × B.X     // +면 한쪽, −면 반대쪽, 0이면 일직선

유도 노트 실험의 "외적 Z" 칸이 바로 이 값이었어요. 위에서 내려다본 평면이라 ⊙(+)와 ⊗(−) 두 가지뿐이었죠.

내적도 "어디"를 말한다 — 단, 앞이냐 뒤냐 두 갈래만

"내적 = 얼마나, 외적 = 어느 쪽"은 반만 맞는 문장이에요. 내적의 부호는 "같은 편인가, 반대 편인가"를 알려 줍니다.

알려 주는 것고를 수 있는 "어디"
내적부호 = 앞/뒤 (같은 편 / 반대 편) · 크기 = 얼마나두 갈래 중 하나
외적어느 축으로 돌아야 B 쪽인가빙 둘러 무수히 많은 옆 중 하나
어디서내적으로 물은 것
터렛 레이더 원뿔타겟이 앞에 있나 → 내적 > cos(반각)
미사일얼마나 돌아야 하나 → Acos(내적)
종이 torqueN이 v 편인가 −v 편인가 → 부호로 축을 뒤집음 + 크기로 세기

종이 torque: 50°와 130°

float3 torque = dot(N, v) * cross(N, v) * FlipStrength;
N과 v 사이외적 길이 (sin)내적 (cos)실제로 도는 쪽
50°0.77+0.64v 쪽으로 50°
130°0.77−0.64축이 뒤집혀 −v 쪽으로 50° (v까지 130°를 돌지 않음)

외적만 보면 둘이 똑같아요(30°/150°와 같은 문제). 내적 부호가 "v가 가깝다 / −v가 가깝다"를 골라 주고, 음수를 곱하면 축이 정반대가 되어 더 가까운 쪽으로 돕니다. 화살표 × 음수 = 반대 방향 화살표 (늘이고 줄이기).

3D 외적 = 2D 외적 세 개 (몰라도 되는 칸)

공식 안쪽은 블랙박스여도 됩니다. 한 칸만 들여다보면, 세 평면에서 각각 2D 외적을 해서 축의 X·Y·Z 칸에 하나씩 넣어 모은 것이에요(FVector::CrossProduct).

축.Z = A.X × B.Y − A.Y × B.X    // 바닥(XY): 위에서 보면 얼마나 옆으로
축.X = A.Y × B.Z − A.Z × B.Y    // 옆벽(YZ)
축.Y = A.Z × B.X − A.X × B.Z    // 앞벽(ZX): 옆에서 보면 얼마나 위·아래로
앞 (1,0,0)일 때 목표 방향축 (X, Y, Z)뜻
오른쪽 앞 (0.87, 0.5, 0)(0, 0, 0.5)위아래 축 — 옆으로만
위쪽 앞 (0.87, 0, 0.5)(0, −0.5, 0)좌우 축 — 고개만 듦
오른쪽 위 앞 (0.7, 0.5, 0.5)(0, −0.5, 0.5)기울어진 축 — 둘 다
정반대 (−1, 0, 0)(0, 0, 0)뒤를 보는 축이 무수히 많아 하나로 못 고름

내가 정리한 문장

2D 에서는 외적도 마찬가지로 그냥 숫자에 불과하지만, 3D 에서는 그런 단순 숫자를 가지고는 방향을 알 수가 없기 때문에 입체적으로 여러 평면들끼리의 외적을 합친 값을 구한다? 맞음

"합친"은 더하는 게 아니라 축의 X·Y·Z 칸에 하나씩 넣어 모은 것.

내적은 어디로 회전해야 하는 게 아닌, 회전해야 하는 양밖에 필요하지 않으니까 굳이 3차원까지 갈 필요가 없다? 반만 맞음

내적도 세 칸을 다 씁니다 (A.X×B.X + A.Y×B.Y + A.Z×B.Z). 고친 문장: 내적도 3차원을 다 쓰지만, "얼마나"는 숫자 하나로 대답할 수 있어서 결과가 숫자다.

앞으로 얼마나, 옆으로 얼마나 라고 하는 건 좀 헷갈리지 않나. 그렇게 따지면 외적으로도 cos와 같은, 얼마나 회전해야 하는 양을 알 수 있다는 건가 좋은 의심 — 이 질문에서 30°/150° 문제가 드러남

외적 길이(sin)로도 각도를 반쯤 알 수 있지만 30°와 150°를 구별 못 함 → 그래서 각도는 내적.

외적은 50도로 돌아도 50도 위치, 130도를 돌아도 50 위치. 이걸 내적을 이용해서 50도로 돌지 130도를 돌지… 그런 느낌인가 맞음 — 30°/150°를 종이에서 스스로 다시 찾음 (2026-10-29)

종이에서는 한 걸음 더: 130°면 v까지 130°를 도는 대신, 내적 음수로 축을 뒤집어 −v 쪽으로 50°만 돈다.
