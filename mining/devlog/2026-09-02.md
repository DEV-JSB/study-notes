## 배운 것 — 언리얼 개념

- **`Content/<프로젝트명>/` 최상위 폴더 원칙** — 내가 만든 에셋을 한 폴더에 몰아넣는 이유는
  정리정돈이 아니라, Fab/마켓 에셋을 **통째로 삭제·업데이트할 수 있게** 하기 위해서다.
  섞여 있으면 외부 에셋을 걷어낼 때 내 것이 딸려 나간다.
- **`__ExternalActors__` = OFPA(One File Per Actor)** — World Partition을 쓰면 레벨의
  액터 하나가 파일 하나로 저장된다. 그래서 액터를 조금만 옮겨도 git diff에 파일이
  수십 개 잡히는데, 그게 정상이다.
- **리다이렉터** — 에셋을 옮기거나 이름을 바꾸면 원래 자리에 눈에 안 보이는 이정표가
  남는다. `Fix Up Redirectors` 로 정리하지 않으면 폴더가 안 지워지고 쿠킹이 실패한다.
- **Live Coding의 함정** — 헤더(`UPROPERTY`, 새 클래스, 멤버 추가)를 바꾸고
  `Ctrl+Alt+F11` 을 누르면 **성공했다고 나오지만 반영되지 않는다.**
  헤더를 건드렸으면 에디터를 끄고 Visual Studio에서 빌드해야 한다.
- **UObject 포인터에 `UPROPERTY()` 가 없으면 GC가 수거해간다** — Unity 감각으로
  멤버 포인터를 들고 있으면 런타임에 갑자기 널이 된다. 입문자 크래시 1위 원인.
- **노멀맵 규약 차이** — 언리얼은 DirectX 규약(초록 채널 아래). 파일명에 `OpenGL` 이
  붙은 노멀맵은 초록 채널이 반대라 빛이 뒤집혀 보인다.
- **Unity(TBH) 습관과 정면 충돌하는 것** — 언리얼은 멤버 변수에 `_` / `m_` 를 **붙이지
  않는다.** 전부 PascalCase. bool만 `b` 접두사. 두 프로젝트를 오갈 때 제일 먼저 티가 나는 부분.
