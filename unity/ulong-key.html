enum 두 개를 ulong 키 하나로 — 숫자 그대로 넣기와 비트 하나씩 켜기

튜플 대신 ulong 하나로 Dictionary 키를 만들던 MakeKey를 두 가지 방법으로 다시 만들어 본 노트. 한 줄 결론: 둘 다 키는 만들어진다. 하지만 enum 하나에 값이 한 번에 하나뿐이면 "숫자 그대로 넣기"가 맞는 도구다. "비트 하나씩 켜기"는 여러 개를 동시에 켜고 끄기 위한 형식이라, 키로 쓰면 32개 제한과 칸 찾기라는 단점만 떠안는다.

발단

회사 프로젝트에서 enum 두 개의 조합으로 Dictionary 키를 만들어야 했던 적이 있습니다. 튜플을 쓰기 싫어서 AI에게 물어 ulong 하나에 두 값을 담는 MakeKey를 썼는데, 그때는 왜 그 모양인지 모른 채 가져다 썼습니다. 기억에 남은 건 "ulong을 나눠서 플래그처럼 세운다"는 흐릿한 말뿐이었습니다.

그 말을 비트 그림으로 바꿔 보니 두 갈래로 나뉘었습니다. 그래서 둘 다 직접 만들어 보고 비교했습니다.

  • A. 숫자 그대로 넣기 (bit packing): 칸 묶음 하나에 enum 번호를 2진수 그대로 넣는다
  • B. 비트 하나씩 켜기 (bit flag): 칸 묶음 안에서 enum 번호번 칸 하나만 켠다
public enum ItemType { Weapon, Armor, Potion, Ring }  // 0, 1, 2, 3
public enum Grade    { Normal, Rare, Epic, Legend }   // 0, 1, 2, 3

직접 눌러 보기 — 키를 만들고 다시 꺼내기

ItemType과 Grade를 고르면 A와 B가 만드는 64비트 키와, 그 키에서 다시 꺼낸 값이 나옵니다. 주황은 Grade가 들어가는 왼쪽 32칸, 파랑은 ItemType이 들어가는 오른쪽 32칸입니다.

이 칸은 스크립트로 계산합니다. 값이 나오지 않으면 파일을 브라우저에서 직접 열어 주세요.

1. 64칸을 왼쪽 32칸과 오른쪽 32칸으로 나눈다

ulong은 64비트입니다. 2진수로 가로로 적으면 맨 왼쪽이 63번 비트, 맨 오른쪽이 0번 비트입니다. 이걸 가운데에서 잘라 반씩 씁니다.

담는 것GradeItemType
다른 문서에서 부르는 이름상위 32비트 (high bits)하위 32비트 (low bits)

64칸은 머릿속에 잘 안 들어옵니다. 아래 그림은 8칸으로 줄여서 그립니다. 왼쪽 4칸이 Grade, 오른쪽 4칸이 ItemType입니다. ulong에서는 4를 32로 바꾸기만 하면 됩니다.

2. enum은 이름이 붙은 int다

C# enum은 따로 정하지 않으면 안쪽 자료형(underlying type)이 int입니다 (공식 문서). ItemType.Armor는 메모리 안에서 그냥 int 1이고, 컴퓨터는 모든 정수를 2진수 비트로 저장합니다.

Ring(3)은 비트가 두 개 켜져 있습니다. 일반 enum은 "비트 하나 = 값 하나"가 아닙니다. 앞 노트의 [Flags] enum은 값을 1, 2, 4, 8로 줘서 항상 비트 하나만 켜지게 합니다. 이 차이가 A와 B를 가릅니다.

3. A 숫자 그대로 넣기

10진수로 먼저

아이템 번호 3과 등급 번호 2를 숫자 하나로 묶으려면 3 × 100 + 2 = 302로 만들면 됩니다. "앞 두 자리는 아이템, 뒤 두 자리는 등급"이라고 약속하면 302만 보고도 둘을 다시 알아낼 수 있습니다. A는 이 일을 2진수로 하는 것입니다.

2진수로 (8칸 예시: Epic(2) + Armor(1))

왼쪽 4칸 (Grade)오른쪽 4칸 (ItemType)값
키001000012 × 16 + 1 = 33
10진수8칸 2진수ulong
앞쪽으로 보내기× 100× 16 = << 4× 2³² = << 32
 
public static ulong MakePackedKey(ItemType itemType, Grade grade)
{
    ulong key = 0;

    key |= (ulong)itemType;           // 밀지 않음 → 오른쪽 32칸
    key |= ((ulong)grade << 32);      // 32칸 밀기 → 왼쪽 32칸

    return key;
}

ulong에서 Epic(2) + Armor(1)의 키는 2 × 2³² + 1 = 8589934593입니다.

(ulong)grade << 32는 먼저 ulong으로 바꾸고 나서 밉니다. 순서를 바꿔 (ulong)((int)grade << 32)로 쓰면 int 안에서 32칸을 밀게 되는데, int 시프트는 횟수를 32로 나눈 나머지만 쓰므로 0칸을 밉니다 (공식 문서, 앞 노트 8절).

4. A에서 꺼내기 — 몫과 나머지

만들 때 "× 2³² 하고 더했다"면, 꺼낼 때는 2³²으로 나눠서 몫과 나머지를 따로 가져갑니다.

10진수8칸 2진수ulong
만들기3 × 100 + 2 = 3022 × 16 + 1 = 33
왼쪽 값 (몫)302 ÷ 100의 몫 = 333 ÷ 16의 몫 = 2key >> 32
오른쪽 값 (나머지)302 ÷ 100의 나머지 = 233 ÷ 16의 나머지 = 1왼쪽 32칸 지우기

직접 밀어 보기 — 8칸에서 >>와 <<

키는 Epic(2) + Armor(1) = 0010_0001입니다. 버튼을 누를 때마다 모든 칸이 한 칸씩 옮겨집니다. 칸의 색은 원래 어느 값의 비트였는지를 뜻하고, 회색은 새로 들어온 0입니다.

왼쪽(Grade) 꺼내기: >>로 끌어내린다

>>는 모든 칸을 오른쪽으로 옮깁니다. 오른쪽 끝을 넘어간 칸은 버려지고, 왼쪽에 새로 생긴 빈칸은 0으로 채워집니다 (ulong 기준). 4칸을 밀면 왼쪽 4칸의 0010이 통째로 오른쪽 4칸으로 이사를 오고, 원래 있던 ItemType은 밀려나서 사라집니다.

public static Grade GetGradeFromPackedKey(ulong packedKey)
{
    ulong key = packedKey >> 32;
    int value = (int)key;
    return (Grade)value;
}

오른쪽(ItemType) 꺼내기: 옮기지 않고 왼쪽만 지운다

ItemType은 이미 0번 칸부터, 즉 원래 있어야 할 자리에 있습니다. 문제는 왼쪽에 붙은 Grade 하나입니다. 지우는 방법을 세 가지 다 만들어 봤고, 결과는 모두 같습니다.

방법코드원리
1. 마스크로 지우기key & ((1UL << 32) - 1)마스크의 왼쪽은 전부 0, 오른쪽은 전부 1. AND는 둘 다 1인 칸만 남긴다
2. 밀어서 떨어뜨렸다가 되돌리기(key << 32) >> 32<< 32에서 Grade가 왼쪽 끝 밖으로 떨어지고, >> 32로 ItemType이 제자리로 온다
3. 작은 상자에 담기(int)key64칸을 32칸 상자로 캐스트하면 안 들어가는 왼쪽 32칸이 잘린다 (공식 문서: 명시적 정수 변환은 높은 쪽 비트를 버림)

세 방법 모두 "ulong 상자는 64칸으로 정해져 있어서, 밖으로 밀려난 비트는 버려진다"는 같은 원리를 씁니다. 실무 코드에서는 의도가 바로 읽히는 방법 1(마스크)이나 3(캐스트)을 더 자주 봅니다 (커뮤니티 표준). 방법 2는 long처럼 부호 있는 자료형에서는 >>가 빈칸을 부호 비트로 채워서 (공식 문서: 산술 시프트) 음수가 나올 수 있습니다.

public static ItemType GetItemTypeFromPackedKey(ulong packedKey)
{
    ulong key = packedKey & ((1UL << 32) - 1);   // 방법 1
    int value = (int)key;
    return (ItemType)value;
}

마스크 (1UL << 32) - 1을 만드는 세 가지 방법

오른쪽 32칸만 1인 수가 필요합니다. 1이 n개인 2진수 = 2ⁿ − 1이라는 건 앞 노트 7절에서 정리했습니다. 세 값은 모두 4294967295입니다.

방법코드설명
계산(1UL << 32) - 11 뒤에 0이 32개인 수에서 1을 뺀다. 1000 − 1 = 999와 같은 원리
16진수0xFFFFFFFFUL16진수 F 한 글자 = 2진수 1111 네 칸. 32칸 ÷ 4 = F 8개 (커뮤니티 표준)
이미 있는 값(ulong)uint.MaxValueuint는 32칸이라 가장 큰 값이 32칸 전부 1

숫자의 값은 0번 칸부터 읽는다. ItemType은 이미 0번 칸부터 있어서 지우기만 하면 되지만, Grade는 4번 칸(ulong에서는 32번 칸)부터 있어서 지워도 2 × 16 = 32로 읽힌다. 그래서 Grade는 반드시 옮겨야 하고, >>로 옮기면 오른쪽 칸은 덤으로 떨어져 나간다.

5. B 비트 하나씩 켜기

B는 앞 노트의 비트 플래그처럼 1 << 번호로 칸 하나를 켭니다. ItemType은 오른쪽 32칸의 itemType번 칸, Grade는 왼쪽 32칸의 grade번 칸입니다.

8칸 예시: Epic(2) + Armor(1)왼쪽 4칸 (Grade)오른쪽 4칸 (ItemType)
A. 숫자 그대로0010 (숫자 2)0001 (숫자 1)
B. 비트 하나씩0100 (2번 칸)0010 (1번 칸)
 
public static ulong MakeFlagKey(ItemType itemType, Grade grade)
{
    ulong itemFlag = 1UL << (int)itemType;                // 오른쪽 32칸의 itemType번 칸
    ulong gradeFlag = (1UL << 32) << (int)grade;          // 왼쪽 32칸의 grade번 칸 = 32 + grade번 칸

    return itemFlag | gradeFlag;
}

6. B에서 꺼내기 — 같은 ulong이라도 형식이 다르다

처음에는 "B에서 ItemType 꺼내기도 A와 똑같이 왼쪽 32칸만 지우면 되지 않나?"라고 생각했습니다. 지운 뒤 남는 오른쪽 32칸을 비교해 보면 다릅니다.

A는 남은 값이 곧 enum 번호입니다. B는 남은 값이 1 << 번호의 결과라서, Potion을 꺼내면 2가 아니라 4가 나옵니다. B에는 "몇 번 칸이 켜져 있나"를 찾는 단계가 하나 더 있습니다.

자료형은 둘 다 ulong이지만 안에 담긴 약속(형식, encoding)이 다르다. ulong만 봐서는 어느 약속으로 만든 키인지 알 수 없으므로, 만드는 메서드와 꺼내는 메서드는 항상 짝이 맞아야 한다.

켜진 칸은 0번 칸부터 하나씩 확인해서 찾았습니다. 앞 노트의 IsOn을 32번 반복하는 것과 같습니다. GetGradeFromFlagKey는 A에서 쓴 >> 32를 먼저 해서 같은 루프를 다시 쓸 수 있게 만들었습니다.

public static ItemType GetItemTypeFromFlagKey(ulong flagKey)
{
    for (int i = 0; i < 32; ++i)
    {
        ulong flag = 1UL << i;

        if ((flagKey & flag) != 0)
        {
            return (ItemType)i;
        }
    }
    return default;
}

public static Grade GetGradeFromFlagKey(ulong flagKey)
{
    ulong key = flagKey >> 32;          // 먼저 왼쪽 32칸을 오른쪽으로 옮긴다
    for (int i = 0; i < 32; ++i)
    {
        ulong flag = 1UL << i;

        if ((key & flag) != 0)
        {
            return (Grade)i;
        }
    }
    return default;
}

8. A와 B는 어떻게 고르나

고르는 기준은 질문 하나입니다. "이 칸 묶음에 들어갈 값이 한 번에 하나인가, 여러 개일 수 있나?"

B의 꺼내기가 어색하게 느껴졌던 건 코드 때문이 아니라 도구를 잘못 골랐다는 신호였습니다.

결과이유
A안전숫자로 넣으니 32칸에 약 42억까지 들어감. 왼쪽이든 오른쪽이든 같음
BGrade 32번부터 깨짐켜야 할 칸이 64번 이상이라 64칸 상자 밖으로 떨어져 gradeFlag가 0이 됨. 에러 없이 키가 겹침

맨 위 "직접 눌러 보기"에서 Grade 32나 39를 눌러 보면 B의 왼쪽 32칸이 비는 것을 볼 수 있습니다. B에서 Grade를 오른쪽에 두었다면 상자 밖으로 떨어지는 대신 ItemType 칸을 침범합니다. 깨지는 모양이 달라집니다.

정리

  1. ulong 64칸을 왼쪽 32칸(상위 비트)과 오른쪽 32칸(하위 비트)으로 나눠 enum 두 개를 담는다. enum은 이름이 붙은 int라서 비트 모양을 그대로 옮길 수 있다
  2. A(숫자 그대로) 만들기: 왼쪽 값은 (ulong)값 << 32, 오른쪽 값은 그대로, OR로 합친다. 밀기 전에 ulong으로 바꾼다
  3. A 꺼내기는 몫과 나머지다. 왼쪽 값은 >> 32 한 번, 오른쪽 값은 왼쪽 지우기(마스크 (1UL << 32) - 1 / << 32 다음 >> 32 / 32칸 자료형으로 캐스트)
  4. 숫자의 값은 0번 칸부터 읽는다. 오른쪽 값은 지우기만, 왼쪽 값은 옮기기가 필요하고 >>가 지우기까지 함께 한다
  5. B(비트 하나씩)는 같은 ulong이라도 형식이 다르다. 꺼낼 때 켜진 칸 번호를 찾는 단계가 더 있고, 만드는 메서드와 꺼내는 메서드는 짝이 맞아야 한다
  6. 값이 한 번에 하나면 A, 여러 개가 동시에 켜지면 B. 키 만들기에는 A가 맞는 도구다
  7. 그냥 쓴 1은 int, -는 <<보다 먼저, AND 결과는 그 칸의 자리값. 이 세 가지는 컴파일러가 잡아 주지 않는다
