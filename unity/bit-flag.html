칸 8개를 int 하나에 담는다 — 비트 플래그와 8×8 격자

체크박스 64개짜리 격자 UI의 켜짐/꺼짐을 비트로 담으며 정리한 개념 노트. 한 줄 결론: 비트 하나 = 칸 하나. 칸을 가리키려면 번호를 1 << 번호로 바꾼 마스크를 만들고, 켜기는 OR, 끄기는 & ~마스크, 뒤집기는 XOR, 확인은 (값 & 마스크) != 0.

발단

체크박스 64개짜리 8×8 격자 UI를 만들면서, 켜짐/꺼짐을 bool 64개가 아니라 비트로 담아 보기로 했습니다. 비트 플래그는 실무에서 여러 번 썼지만, 연산 하나하나가 왜 그 모양인지 한 번에 정리해 둔 적이 없어서 이번에 개념부터 다시 묶었습니다.

직접 눌러 보기 — 한 줄(8칸)에 네 가지 연산

위 줄은 현재 값 flags, 아래 줄은 고를 칸 mask입니다. 칸을 눌러 바꾸면 네 연산의 결과가 바로 계산됩니다. 2진수는 오른쪽 끝이 0번 비트입니다.

이 칸은 스크립트로 계산합니다. 값이 나오지 않으면 파일을 브라우저에서 직접 열어 주세요.

flags (현재 값) — 눌러서 켜고 끄기
mask (고를 칸) — 칸 하나를 고르면 1 << 번호
동작식2진수10진수

1 · 비트 번호와 비트 값은 다르다

비트 하나를 부르는 방법이 두 가지 있습니다.

  • 비트 번호: 오른쪽 끝부터 0, 1, 2, … 로 센 자리 번호. 배열 인덱스처럼 0부터 셉니다
  • 비트 값: 그 자리 하나만 1인 수. 1 << 번호로 만듭니다
비트 번호비트 값 1 << 번호2진수
010000_0001
120000_0010
240000_0100
380000_1000
71281000_0000

<<(왼쪽 시프트)는 1을 왼쪽으로 번호만큼 밉니다. 한 칸 밀 때마다 2배가 되므로 1 << n은 2ⁿ입니다.

연산에 넣는 것은 항상 값(마스크)입니다. 번호를 그대로 넣으면 숫자 3(0000_0011)처럼 엉뚱한 칸 두 개를 가리키게 됩니다.

2 · 플래그 값은 2의 거듭제곱이어야 한다

여러 플래그를 정수 하나에 담으려면 플래그 하나가 비트 한 칸을 혼자 차지해야 합니다. 값을 1, 2, 3, 4로 주면 겹칩니다.

이름값2진수
A10001
B20010
C30011
D40100

A와 B를 같이 켜면 0001 | 0010 = 0011인데, 이건 C와 같은 값입니다. "C 하나만 켜짐"과 "A와 B가 켜짐"을 구분할 수 없습니다. 그래서 값은 1, 2, 4, 8, … 즉 2의 거듭제곱이어야 합니다.

더 알아 두면 좋은 것 — [Flags]는 값을 정해 주지 않는다

C#의 [Flags]를 붙여도 값이 자동으로 2의 거듭제곱이 되지는 않습니다. enum의 기본값은 그대로 0, 1, 2, 3이고, [Flags]는 ToString()이 "Poison, Stun"처럼 여러 이름을 출력하게 해 주는 정도입니다 (공식 문서). 값은 직접 줍니다 (커뮤니티 표준).

[Flags]
enum Status
{
    None   = 0,
    Poison = 1 << 0, // 1
    Stun   = 1 << 1, // 2
    Burn   = 1 << 2, // 4
}

3 · 네 가지 연산 — 켜기, 끄기, 뒤집기, 확인

예시는 모두 flags = 0000_0101(0번과 2번 칸이 켜짐), mask = 0000_0100(2번 칸)으로 계산합니다.

동작코드계산결과
켜기 (set)flags | mask0000_0101 | 0000_01000000_0101
끄기 (clear)flags & ~mask0000_0101 & 1111_10110000_0001
뒤집기 (toggle)flags ^ mask0000_0101 ^ 0000_01000000_0001
확인 (check)(flags & mask) != 00000_0101 & 0000_01000000_0100 → 켜짐
연산마스크의 1인 자리에 하는 일
OR |1로 칠한다
AND &그 자리만 남긴다 (거름망)
XOR ^뒤집는다
NOT ~마스크 없이 전부 뒤집는다. 끄기용 거름망을 만들 때 쓴다

다른 연산으로는 안 되는 이유

  • 끄기를 AND만으로: 0000_0101 & 0000_0100 = 0000_0100. 끄려던 칸만 남고 나머지가 꺼집니다. 거름망을 뒤집어(~mask = 1111_1011) "그 칸만 빼고 남기기"로 바꿔야 합니다
  • 뒤집기를 NOT으로: ~0000_0101 = 1111_1010. 마스크가 들어갈 자리가 없어서 모든 칸이 뒤집힙니다
  • 확인을 OR로: OR는 마스크 자리를 항상 1로 만들어서 결과가 0이 되지 않습니다. 꺼진 1번 칸도 0000_0101 | 0000_0010 = 0000_0111, "켜짐"이 나옵니다. 확인은 AND로만 됩니다

XOR — 둘이 다르면 1

XOR(배타적 OR, exclusive OR)는 두 비트가 서로 다르면 1, 같으면 0입니다. 마스크 비트 b를 기준으로 읽으면, b가 0인 자리는 a가 그대로, b가 1인 자리는 a가 뒤집혀 나옵니다. 그래서 "뒤집기"입니다.

ab (마스크)a ^ b읽는 법
000b가 0 → a 그대로
101
011b가 1 → a 뒤집힘
110

4 · C#에서 쓸 때 조심할 문법

int는 bool로 자동으로 바뀌지 않는다

row & mask의 결과는 int입니다. C#은 int를 bool로 바꿔 주지 않으므로 (공식 문서), 확인은 0과 비교해서 bool을 만듭니다. 비교 대상은 1이 아니라 0입니다. 거른 결과는 "0이거나, 그 칸의 값이거나" 둘 중 하나라서, 3번 칸이 켜져 있으면 1이 아니라 8이 나옵니다.

!=가 &보다 먼저 계산된다

쓴 코드C#이 읽는 방식
row & mask != 0row & (mask != 0) → int & bool이라 컴파일 에러
(row & mask) != 0의도대로

C#에서 !=는 &보다 우선순위가 높습니다 (공식 문서: 연산자 우선순위). 비트 연산과 비교를 한 줄에 섞을 때는 괄호부터 칩니다 (커뮤니티 표준). 결과를 변수에 먼저 담아 두면 괄호 문제 자체가 생기지 않습니다.

int masked = row & mask;
return masked != 0;

5 · 8×8 격자를 int 8개에 담기

int 하나가 가로 한 줄(8칸)을 맡고, 그 int의 0~7번 비트가 그 줄의 칸 8개입니다. y는 배열 인덱스 _bits[y], x는 비트 번호(마스크 1 << x)입니다.

직접 눌러 보기 — 칸을 누르면 _bits[y] ^= 1 << x

왼쪽 격자를 누르면 오른쪽에 줄마다의 int 값이 2진수와 10진수로 나옵니다. 칸 위에 마우스를 올리면 그 칸이 어느 줄의 몇 번 비트인지 보입니다.


    

    
칸 위에 마우스를 올려 보세요

    

      
      
      
    

  



public class BitGrid
{
    public const int Size = 8;

    private readonly int[] _bits = new int[Size];

    public bool IsOn(int x, int y)
    {
        int bit = 1 << x;
        int row = _bits[y];
        return (row & bit) != 0;
    }

    public void Set(int x, int y)
    {
        int bit = 1 << x;
        _bits[y] |= bit;
    }

    public void Clear(int x, int y)
    {
        int bit = 1 << x;
        bit = ~bit;
        _bits[y] &= bit;
    }

    public void Toggle(int x, int y)
    {
        int bit = 1 << x;
        _bits[y] ^= bit;
    }
}

  
Set, Clear, Toggle은 값을 바꾸는 메서드라서, 계산한 결과를 _bits[y]에 다시 넣어야 합니다. _bits[y] ^ bit;처럼 식만 쓰면 결과를 버리는 줄이 되어 컴파일 에러(CS0201)가 납니다. ^=, |=, &=는 "계산하고 그 자리에 다시 넣기"를 한 번에 쓰는 복합 대입입니다.


  
다른 설계: ulong 하나에 64칸

  

    
int[8] (줄마다 int 하나)ulong 하나

    
      
(x=3, y=2)의 위치_bits[2]의 3번 비트비트 번호 y * 8 + x = 19

      
마스크1 << 3 = 81UL << 19

      
저장·비교배열이라 복사·비교에 반복문숫자 하나라 대입, == 비교가 바로 됨

      
남는 비트int 하나당 32비트 중 24비트를 안 씀 (byte[8]이면 없음)없음

    
  

  
ulong을 쓸 때는 반드시 1UL << index로 씁니다. 1 << index의 1은 int라서, C#은 시프트 횟수를 32로 나눈 나머지만 씁니다 (공식 문서). 1 << 40은 1 << 8 = 256이 됩니다. 이 실수는 비트 번호 0~31인 칸(y = 0~3)에서는 드러나지 않고, 32~63인 칸(y = 4~7)에서만 엉뚱한 칸이 켜지는 모양으로 나타납니다.






  
6 · 한 줄 전체를 한 번에 — 0과 2ⁿ − 1

  
int 하나가 한 줄 8칸 전체이므로, 줄 하나를 통째로 대입하면 8칸이 한 번에 바뀝니다. 칸마다 반복할 필요가 없습니다. 끄기는 0000_0000 = 0, 켜기는 1111_1111 = 255입니다.

7 · 1이 n개인 2진수 = 2ⁿ − 1

  
1111_1111이 255라는 것을 자리값을 하나하나 더하지 않고 바로 아는 방법입니다.


  
10진수로 먼저: 999 = 1000 − 1

  
999에 1을 더하는 과정을 자리마다 보면 이렇습니다.

  

    
자리계산쓰는 값다음 자리로 올림

    
      
일의 자리9 + 1 = 1001

      
십의 자리9 + 올림 1 = 1001

      
백의 자리9 + 올림 1 = 1001

      
천의 자리올림 11없음

    
  

  
결과는 1000입니다. 9는 10진수 한 자리에 쓸 수 있는 가장 큰 숫자라서, 9로 꽉 찬 수에 1을 더하면 올림이 맨 앞까지 이어지고 "1 뒤에 0이 n개"가 됩니다. 그래서 9가 n개인 수 = 10ⁿ − 1입니다 (99 = 100 − 1, 999 = 1000 − 1).


  
2진수에서는 1이 "꽉 찬 자리"다

  
2진수 한 자리에 쓸 수 있는 가장 큰 숫자는 1입니다. 1 + 1은 2인데 2진수에는 2라는 숫자가 없으므로, 10(0을 쓰고 1을 올림)이 됩니다. 10진수의 9 + 1과 같은 상황입니다. 0111에 1을 더해 보면:

  

    
자리계산쓰는 값다음 자리로 올림

8 · 격자를 키우면 — 32칸에서 생기는 두 가지 함정

  
int는 32비트라서 한 줄에 32칸까지 담을 수 있습니다. 다만 32번째 칸(31번 비트)에서 두 가지가 걸립니다.

  
① 31번 비트는 부호 비트(sign bit)다

  
int는 맨 위 비트가 1이면 음수입니다 (공식 문서). 1 << 31은 -2147483648입니다.

  

    
연산31번 칸에서

    
      
켜기·끄기·뒤집기비트 연산은 부호와 상관없이 그대로 동작

      
확인 != 0동작

      
확인 > 0음수라서 꺼짐으로 잘못 판단

    
  

  
확인을 "0보다 크냐"가 아니라 "0과 다르냐"로 쓰는 이유가 여기서도 나옵니다.

  
② 전부 켜기 식이 깨진다

  
32칸이면 (1 << 32) - 1이 필요한데, int 시프트는 횟수를 32로 나눈 나머지만 쓰므로 1 << 32 = 1 << 0 = 1입니다. 1 − 1 = 0이라서 전부 켜기가 아무것도 켜지 않습니다.

  

    
해결내용

int 그대로전부 켜기에 -1(= ~0, 32비트 전부 1). 값을 출력하면 음수로 보인다

      
32칸보다 많이ulong (64비트). 마스크는 1UL << n
