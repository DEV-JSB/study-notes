좌표가 커지면 캐릭터가 멈춘다 — float 정밀도

오래 켜 둔 유저의 캐릭터 이동에 문제가 생겼던 일을, 빈 씬에서 다시 만들어 재고 float의 구조까지 내려가서 정리한 기록. 한 줄 결론: float은 2진수 24자리를 정수 부분과 소수 부분이 나눠 쓴다. 좌표가 커지면 소수 자리가 모자라서, 작은 이동은 반올림으로 사라진다.

글 버전 float-precision.md · 실습 원본 unity-study / 04.FloatPrecision

발단

실무 프로젝트(TBH)는 캐릭터가 왼쪽에서 오른쪽으로, 좌표 한 축을 따라 계속 이동하는 구조입니다. 이동은 float 속도에 deltaTime을 곱해 좌표에 더하는 방식이었습니다.

스테이지를 옮기거나 재시작하면 좌표를 0으로 되돌리기 때문에, 좌표가 크게 쌓이지 않는다는 전제로 설계했습니다. 그런데 같은 스테이지를 반복할 때는 0으로 되돌리는 코드가 없었고, 게임을 오래 켜 둔 유저에게서 문제가 생겼습니다.

원인을 따라가 보니 두 가지가 걸려 있었습니다.

  • 좌표(Transform.position)는 float이라서 값이 커질수록 표현할 수 있는 간격이 넓어진다
  • 그 상태에서는 작은 이동값을 더해도 좌표가 변하지 않을 수 있다

둘 다 이번에 처음 제대로 들여다봤습니다. 그리고 좌표를 0으로 되돌린다는 전제가 스테이지 반복 경로에서는 성립하지 않았습니다.

그래서 "좌표가 얼마일 때, 얼마짜리 이동이, 실제로 얼마나 먹히는가"를 직접 재고, 왜 그런지 float의 구조까지 내려가서 정리했습니다. 이 노트에는 회사 코드가 없습니다. 같은 조건을 빈 씬에서 다시 만들어 쟀습니다.

직접 넣어 보기 — 이 좌표에서 이 Speed는 실제로 얼마가 되나

좌표와 Speed(1초에 가는 거리)를 넣으면, 60프레임 기준으로 한 프레임의 이동이 어떻게 반올림되는지 보여 줍니다. 계산은 브라우저에서 실제 32비트 float 덧셈으로 합니다.

이 칸은 스크립트로 계산합니다. 지금 보이는 화면이 미리보기(스크립트가 꺼진 화면)라면 값이 나오지 않으니, 파일을 브라우저에서 직접 열어 주세요.

1 · 배경 지식 ① — 2진수에도 자릿값이 있다

10진수는 자리가 왼쪽으로 하나 갈 때마다 10배, 소수점 오른쪽으로 하나 갈 때마다 10으로 나눈 값입니다. 2진수는 똑같은 줄인데 10 대신 2예요.

  • 소수 자리가 n개 있으면 맨 끝자리 하나의 값보다 잘게는 표현할 수 없습니다
  • 소수 4자리면 맨 끝자리는 1/16 = 0.0625. 표현할 수 있는 소수 부분은 0, 1/16, 2/16, 3/16, … 뿐

2 · 배경 지식 ② — 2진수로 몇 자리인지 세는 법 (변환하지 않고)

2진수로 바꿔 쓰지 않아도 자릿수는 셀 수 있습니다. 10진수에서 "4,321은 1,000 이상 10,000 미만이니 4자리"라고 하는 것과 같아요.

방법하는 일13으로 해 보면답
곱해서 올라가기1, 2, 4, 8, … 으로 2배씩 키우다가 내 수를 넘기 직전까지 몇 개였는지 센다1, 2, 4, 8 (16은 넘음)4자리
나눠서 내려가기내 수를 2로 계속 나눠(나머지는 버림) 0이 될 때까지 몇 번 나눴는지 센다13 → 6 → 3 → 1 → 04자리

실제로 13은 2진수로 1101, 4자리입니다. 좌표에서 자주 만나는 범위는 이렇습니다.

3 · 배경 지식 ③ — float은 32칸짜리 상자, 숫자에 쓸 수 있는 건 24자리

1,000,000은 2진수로 20자리입니다 (524,288 이상 1,048,576 미만). 24자리 중 20자리를 정수가 썼으니 소수에는 4자리만 남고, 맨 끝자리 값은 1/16 = 0.0625. 1,000,000 근처에서는 0.0625보다 잘게 좌표를 구분할 수 없습니다.

11110100001001000000 . _ _ _ _
└──── 정수 20자리 ────┘ └ 소수 4자리 ┘
                        1/2 1/4 1/8 1/16

1,000,000        0 | 10010010 | 11101000010010000000000
1,000,000.0625   0 | 10010010 | 11101000010010000000001   ← 끝자리 +1 이 바로 다음 float

float의 구조는 IEEE 754 표준 · 비트 값은 PC에서 직접 뽑아 확인

4 · 눈금 간격 — 좌표가 2배 커지면 간격도 2배

이웃한 두 float 사이의 거리를 이 노트에서는 눈금 간격이라고 부릅니다. 구하는 순서는 세 단계예요.

좌표가 2배가 되면 정수 부분이 한 자리 늘고, 소수 자리가 하나 줄어서, 눈금 간격이 2배가 됩니다. 0에 가까울수록 눈금이 촘촘하고, 멀어질수록 성겨집니다.

5 · 더한 결과는 가장 가까운 눈금으로 간다

float 덧셈의 결과가 눈금 사이에 떨어지면 가장 가까운 눈금으로 반올림됩니다 (IEEE 754 표준의 기본 방식). Mathf.RoundToInt와 같은 원리예요. RoundToInt는 눈금 간격이 1인 자이고, float은 눈금 간격이 좌표에 따라 달라지는 자입니다.

  • 더하는 값이 눈금 간격의 절반보다 작으면 원래 눈금이 더 가까워서 제자리로 돌아옵니다. 이동이 사라집니다
  • 절반보다 크면 다음 눈금으로 갑니다. 이때 더한 값이 얼마든 눈금 한 칸만큼 갑니다
float x = 1_000_000f;   // 눈금 간격 0.0625
x += 0.02f;             // 0.32칸 → 0칸으로 반올림. x는 그대로 1,000,000
x += 0.04f;             // 0.64칸 → 1칸으로 반올림. x는 1,000,000.0625 (0.04를 더했는데 0.0625가 늘었다)

7 · Unity에서 직접 잰 결과

Unity 6000.0.72f1 · 에디터 · 빈 씬에 부모 없는 오브젝트 하나 · 매 프레임 1/60초로 고정해서 이동 · 60프레임마다 요약을 Console에 출력

재는 방법: 더하려던 값과 실제로 늘어난 좌표를 나란히 비교합니다. (FloatPrecision.cs)

float requested = _speed * deltaTime;               // 더하려던 이동량

float before = transform.position.x;
transform.position += new Vector3(requested, 0f, 0f);
float after = transform.position.x;

float actual = after - before;                      // 실제로 늘어난 좌표

눈금 간격은 float의 비트를 정수로 꺼내 1을 더해서 구했습니다. 3절의 "본체 맨 끝자리 +1"을 코드로 한 것입니다.

float next = BitConverter.Int32BitsToSingle(BitConverter.SingleToInt32Bits(abs) + 1);
return next - abs;   // 바로 다음 float까지의 거리

8 · 화면도 같이 깨진다

좌표를 1,000,000으로 두면 이동만 틀어지는 게 아니라 물체가 제대로 그려지지 않습니다. 씬뷰에서 3D 물체가 일그러지고 떨리는 것을 직접 봤습니다. 원인은 같아요. 물체는 점(정점, vertex)들을 이어 붙인 것이고, 그 점의 좌표도 float입니다 (엔진 표준). 점마다 따로 눈금에 반올림됩니다.

점의 월드 좌표 = 물체의 좌표 + 물체 안에서의 위치     (설명용으로 줄인 식)

  • 지름 1은 눈금으로 16칸입니다. 매끈한 곡면을 16칸짜리 계단으로 그리는 셈
  • 스프라이트도 같습니다. 점이 4개인 사각형이라, 사각형이 프레임마다 조금씩 다른 크기로 그려지고 그 위의 픽셀이 늘어나 보입니다

9 · 같은 문제가 숨어 있는 다른 곳 — 시간 누적

좌표만의 문제가 아닙니다. float에 작은 값을 계속 더해 가는 모든 변수가 같은 길을 갑니다.

private float _playTime;

private void Update()
{
    _playTime += Time.deltaTime;   // 60프레임이면 한 프레임에 약 0.0167
}
_playTime눈금 간격0.0167을 더하면일어나는 일
262,144초 전까지 (약 3일 전까지)0.015625 이하1칸 이상조금씩 틀어지지만 거의 정상
262,144초부터 524,288초 전까지 (약 3일부터 6일까지)0.031250.53칸 → 1칸 = 0.03125시간이 약 1.9배 빨리 감
524,288초부터 (약 6일)0.06250.27칸 → 0칸시간이 멈춤
  • 하루는 86,400초. 524,288 ÷ 86,400 = 약 6.07일
  • 이 표는 계산입니다. 직접 6일을 켜 두고 재지는 않았습니다
  • 오버플로우가 아닙니다. float의 최댓값은 0이 38개쯤 붙는 수라서 이런 식으로는 닿지 않습니다

좌표를 주기적으로 0 근처로 되돌린다스테이지 이동·재시작뿐 아니라 스테이지 반복 때도 캐릭터와 주변 물체를 함께 원점 쪽으로 옮긴다. 이번 문제의 직접 원인이 이 리셋이 빠진 것이었다커뮤니티 표준 (floating origin)
누적은 double로, 넘길 때만 float으로double은 2진수 53자리라 눈금이 훨씬 촘촘하다. 다만 Transform.position 자체는 float이라 좌표에는 쓸 수 없고, 시간·거리 누적 같은 내 변수에만 쓸 수 있다공식 문서 (C# 자료형)
좌표가 커질 일이 없는 구조로 만든다캐릭터를 움직이지 않고 배경을 움직이는 식취향 · 바꿔도 됨

정리

  • Unity 좌표는 float이고, float은 2진수 24자리를 정수 부분과 소수 부분이 나눠 쓴다
  • 좌표가 2배 커질 때마다 눈금 간격이 2배가 된다. 1,000,000에서 0.0625, 2,000,000에서 0.125
  • 더한 결과는 가장 가까운 눈금으로 반올림된다. 한 프레임 이동량이 눈금 간격의 절반보다 작으면 사라진다
  • 멈추기 전에 속도가 먼저 틀어지고(느려지거나 빨라짐), 화면도 같이 깨진다
  • 0으로 되돌리는 코드가 모든 경로에 있는지 확인해야 한다. 한 경로만 빠져도 오래 켜 둔 유저에게서 터진다
